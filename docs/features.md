# アプリ機能情報

Thundoku Shelf Desktop は、技術書典・BOOTH で購入した本の管理・閲覧を目的とした
デスクトップアプリケーション（macOS / Windows）です。Web 版
（https://thundoku-shelf-staging.megablacklabel.workers.dev/）の機能をローカルで
再現し、追加でデスクトップ固有の機能を備えています。

- 技術: Rust + GPUI（zed の GUI フレームワーク）+ gpui-component
- ストレージ: SQLite（ローカルファイル）+ .opfspack（画像アーカイブ）
- 依存: `mise` でツールチェーン管理（`mise run <task>`）

## 使用ライブラリ

### GUI

| ライブラリ | 用途 |
|---|---|
| `gpui`（zed-industries/zed） | ウィンドウ・レイアウト・描画・イベントなど GUI の土台 |
| `gpui-component`（longbridge） | ボタン・入力・ポップオーバー・スライダー・スピナー・メニュー等の部品 |
| `gpui-component-assets` / `gpui-base` / `gpui-wry` | gpui-component のアセット・基盤・WebView バックエンド |
| `gpui_platform` | macOS / Windows のプラットフォーム実装（font-kit, runtime_shaders） |
| `resvg` / `usvg` | SVG のレンダリング（アイコン等） |

### データベース・ストレージ

| ライブラリ | 用途 |
|---|---|
| `sqlx` | SQLite への非同期アクセス（sqlite / runtime-tokio / migrate） |
| `tokio` | 非同期ランタイム（sqlx 用） |
| `opfspack`（自作 crate） | .opfspack アーカイブの読み書き（バイト互換で Web 版と互換） |

| `dirs` | OS ごとのデータ保存先の解決（macOS / Windows） |

### 画像・PDF

| ライブラリ | 用途 |
|---|---|

## 起動（単一インスタンス）

同時に起動できるアプリは 1 つだけ。2 個目の起動はウィンドウを開かずに終了します
（多重起動すると DB・パック・ダウンロード先を共有してしまい、二重取り込みや
Google OAuth のループバックポート（`127.0.0.1:38387`）の取り合いが起きるため）。

- **仕組み**: config ディレクトリ（`dirs::config_dir()/thundoku-shelf/instance.lock`）の
  ロックファイルを OS のファイルロックで排他する。Unix は `flock` / Windows は
  `LockFileEx` で、どちらも `std::fs::File::try_lock` が吸収するため
  プラットフォーム分岐は無い（`thundoku_core::single_instance::InstanceGuard`）
- **ロックファイルの場所**: データ保存先（設定で変更可能）ではなく config ディレクトリに
  置く。保存先を変更しても「同時に動くアプリは 1 つ」を保つため
- **クラッシュ復帰**: ロックはプロセスに紐づくため、強制終了でも OS が解放する。
  古いロックが残って起動できなくなることはない（ロックファイル自体は残る）
- **2 個目の挙動**: 外部からは静かに終了する（`exit 0`）。痕跡はログに残る
  （Windows は `%TEMP%\thundoku-shelf\thundoku.log` に追記。ログファイルは追記式で
  開くため、2 個目の追記が起動中インスタンスの書き込みに上書きされない。
  増え続けないよう、起動時に 4MB を超えていたら捨てる）。既存ウィンドウの前面化はしない
- **フォールバック**: ガードを取得できない場合（config ディレクトリが解決できない、
  ロックファイルが開けない等）は起動を止めずに続行する

## 主な画面

### 本棚（Bookshelf）

- **表示モード**: カードグリッド / リスト（視点切替ボタン）
- **グリッドの仮想化**: GPUI の `List` による行単位の仮想表示。画面に見えている
  行だけを構築するため、数百件のカードでもスクロールが軽い
- **リスト表示の行**: 4 列（`表紙(200x133 固定)` / `情報列(320px 固定)` /
  `タグ情報エリア(行幅の 20%)` / `関連書籍カルーセル(残り幅いっぱい)`）。
  情報列は タイトル / 購入日 / サークル・作者 / ページ数 / 状態 の縦並び
  - 表紙も情報列も**固定サイズ**なので、行の高さが内容（タグの折返し等）で変わっても
    テキストの開始 X が全行で揃う（旧: 表紙が行の高さに追従して幅が変わり、行ごとにずれていた）
  - **未読 / 読書中 / 既読 / ダウンロード済み / お気に入り**はサムネイルに重ねず、
    **ページ数の下**に出す。文字タグは短い「未読 / 読書中 / 既読」だけ（四角い `Tag`。
    読書中は `TagVariant::Info` = 青系）。「ダウンロード済み / 未ダウンロード」
    「お気に入り」は文字だと長くて行が変な折り返しになるため、**アイコン**で出す
    （`HardDrive` / `Cloud` / `HeartFilled`・`Heart`、16px・テーマ別の色・tooltip で意味を補う）。
    お気に入りは**登録 / 未登録の両方**を出し、未登録は控えめな輪郭ハートにする。
    お気に入りアイコンは**クリックでトグル**する（`bookshelf_items` + `books` を更新。
    行クリックへ伝播させないのでビューアー / ダウンロードは走らない）
  - **タグ情報エリア**: タグ（サークル / 作者チップと同じチップ）を**行幅の約 20%**に収め、
    入りきらなければその中で折り返す。折り返し行は `content_start()` で**上詰め**にする
    （既定の `align-content: stretch` だと行が列の高さいっぱいに伸び、タグが無い / 少ない本では
    編集ボタンが縦中央に落ちて他の列と頭が揃わない）
  - タグは**表示エリア（タグ列）の幅から入る個数を計算**して出し、入りきらない分は「+n」チップに
    畳む。個数の固定上限は持たない（窓が広いほど多く出る）。計算は「タグ名の実測幅
    （GPUI のテキスト計測）+ チップの装飾」をタグ列の幅に詰め、折り返し 4 行
    （`LIST_TAG_MAX_ROWS` = 表紙の高さ 133px ÷ チップ 1 行 ≈ 29px）を上限にする
    - 実測（「タグ01」形式のタグ 20 件・リスト表示）: 窓 700px = 1 件 / 1000px = 7 件 /
      1400px = 11 件 / 1920px = 15 件。このとき行の高さはタグ無しの行と同じ 150px のまま
      （4 行を超えないので伸びない）。※テストはサイドバー無しの窓なので、サイドバー
      （`SIDEBAR_W`）を引く計算より実際の行は広い = ここに出る数は下限
    - チップ 1 個ぶんの幅すら入らない極端に狭い窓では 1 件だけ出し、「+n」は次の行へ
      折り返す（行が 1 行ぶん伸びる。個数を 0 にして「+n」だけの行にしない）
  - タグの折り返しで行の高さが伸びると、固定サイズの表紙 / カルーセルとの間に大きな余白が
    できるため、行の高さがタグ列に支配されないようにする。「+n」をクリックすると
    **全タグを表示**して列（= 行）が伸び、チップが「閉じる」に変わって折りたたみへ戻せる
    （展開状態は行ごとに view が保持。`tag-toggle-<database_id>`）
  - **タグの並び順**（カード / リスト / お気に入りタグ一覧）: **選択中 → お気に入り → 集計数
    （そのタグを持つカード数）の多い順 → 名前順**。集計は `reload` 時にカードのタグから数える
    （`count_tag_usage`。追加の SQL は無し）ので、タグの追加・削除や取り込みで集計が変わると
    次の reload で並びが変わる。
    お気に入りはチップのハートを押した瞬間に並び替わる（`TagOrder` を描画ごとに作り直す。
    reload は不要）。ハートの塗り分けも同じ `TagOrder` を見る。折りたたみ時もお気に入りタグは
    先頭なので畳まれない
    - **選択中のタグも先頭に出す**（折りたたみ中に隠れないように）。選択を解除すると集計数 /
      名前順の元の位置に戻る。フィルタで絞り込んだタグは結果の本すべてに出るタグなので、
      畳まれて見えなくなるのを防ぐ（`selected_tag_stays_visible_when_collapsed`）
  - **カード（グリッド）のタグ**: `CARD_TAGS_COLLAPSED_MAX`（6 件）で折りたたみ、残りは「+n」チップ
    （リストと同じ `tag-toggle-<database_id>` / 展開状態を共用。展開中のラベルは「閉じる」）。
    カードは**行の高さを共有する**ため、1 冊のタグ数で行全体が間延びする。幅 190px のカード
    （`p_3` の内容幅 166px）で実測: タグ無し = 296.5px、6 件 = チップ 3 行・+90.0px、
    20 件を展開 = 10 行・+295.0px（タグ名は「タグ01」= 2 文字 + 2 桁）
    - 実データ（`book_tags` 276 件）ではタグ名の 77% が 4 文字以下（チップ 2 個 / 行）、
      1 冊あたり最大 14 タグ。上限が無いとカードごとに 1〜10 行までばらつくのが元の崩れ
    - 長いタグ名（「長いタグ名前01」= 6 文字 + 2 桁）だけの本では 6 件で 6 行・+149.0px まで
      伸びる。行をこれ以上伸ばしたくない場合は上限を下げる（`CARD_TAGS_COLLAPSED_MAX`）
  - **並び替えの負荷**（実測・debug ビルド）: 集計は 1000 冊 × 30 タグ（30,000 件）で 33.7ms、
    1 フレーム分（可視 25 冊 × 30 タグ）の並び替えは 1.06ms。並び替えは**可視カードだけ**なので、
    お気に入りの付け外し（`TagOrder` の作り直し + 並び替え）で reload は走らない
  - **関連書籍カルーセル**（タグ情報エリアの右側）: 同一サークル → 同一作者の順に最大 5 件。
    ツールチップで作品名、クリックでビューアー（ローカル本）/ ダウンロード（未取得）。
    関連が無い本にはカルーセル自体を出さない
  - カルーセルのサムネイルは**カルーセル列の幅を 2 等分**して埋める（アイテム幅 =
    列幅 ÷ 2）。大きさの上限はリストの表紙と同じ（実測: 1484px 幅で 196x130 ≒ 表紙
    200x133）。列幅が広いときは上限に当たり、3 枚目が少し覗く（旧: 固定 162px で
    3.5 枚ぶんの幅に 162px を並べていた）。3:2 の枠に比率を保って収める = 切り抜きしない
  - カルーセルは `gpui-kit` の `Carousel`。`CarouselState` は行ごとに view が保持し、
    `reload` で関連件数が変わったときだけ作り直す
  - 前へ / 次へは**自前の四角いバー**（高さはサムネイルと同じ、幅 26px、tooltip は
    日本語の「前へ / 次へ」）。組み込みの `CarouselPrevious` / `CarouselNext` は円形で、
    しかもコンテンツ枠の**外側**に絶対配置されるため next がリストの `overflow_hidden` で
    切れて見えなかった。バーは通常の flex 要素として並べる
  - バーは移動できる向きだけホバーで色が変わる（`theme.secondary` はダークで背景の
    `muted` と同色 15% のため変化が見えない。`views::hover_bg` のモード別グレーを使う）。
    移動できない向きは **Button の disabled と同じ薄さ**（アイコン
    `muted_foreground.opacity(0.5)` + 背景 `muted.opacity(0.4)`）にしてホバー / `cursor_pointer`
    を付けない = **無効表示**
  - バーは**移動できない向きでもクリックハンドラを必ず登録**して `stop_propagation` する
    （登録が無いと移動不可のバーのクリックが行へ抜けてビューアーが開く）。
    `select_next` / `select_previous` は移動できる向きだけ呼ぶ
  - スナップの速さはテーマの `motion.spring_move` を上書きする（カルーセルに個別設定が無いため
    `main.rs` で指定: 既定 280ms / 減衰 0.85 → **120ms / 0.9**）。実測で静止までの時間が
    256ms → 136ms になる
  - 行が高くなったとき（タグ展開）は、カルーセルも表紙と同じく**上揃え**にする
  - 行のクリックは本文（タイトル等）と同じ経路（ローカル本は開く / 未取得は取り込む）。
    カルーセル内のクリックは `stop_propagation` で行クリックへ伝播させない
- **フィルタ**:
  - サイト（すべて / 技術書典 / BOOTH）
  - 検索（タイトル・サークル名）
  - タグ（OR 条件）、イベント、読了状態（未読 / 読書中 / 既読 / お気に入り）
  - **イベントフィルタは技術書典の本棚のときだけ出す**（それ以外のサイトでは概念が無いため
    非表示。以前は BOOTH 以外で出ていた）
- **並び替え（ソート）**: ツールバー 2 段目の右グループ、**表示切替ボタンの左隣**の
  「並び替え」ボタン（Popover）。現在の項目と方向をボタンに常時表示する
  （例: 「並び替え: 購入日 新しい順」）
  - **項目**（単一選択）: 購入日（既定）/ 発売日 / タイトル / 最終閲覧日 / 閲覧回数 /
    閲覧時間 / サイズ
  - **方向**（単一選択）は項目に合った言葉にする（日付 = 新しい順 / 古い順、
    回数 = 多い順 / 少ない順、サイズ = 大きい順 / 小さい順、タイトル = A→Z / Z→A）
  - **選択 UI は gpui-kit の `Radio`（`component::radio::Radio`）**を使う（自前で丸を描かない）。
    項目・方向それぞれが単一選択のラジオで、選択中は塗りつぶし・未選択は枠のみ
  - 選んだらメニューを閉じる。**選択済みの項目をもう一度押しても何も変わらない**（ラジオの
    意味論どおり。方向は「方向」セクションで選ぶ）。「既定に戻す」で購入日（新しい順）に戻る
  - **日付は正規化して比較する**（`date_sort_key`）。サイトごとに形式が違うため
    （技術書典 = RFC3339 / BOOTH・DLsite = `YYYY/MM/DD` / FANZA = `YYYY年MM月DD日`）、
    生の文字列では全サイト横断で時系列に並ばない。値なしは方向に関係なく末尾
  - **データが無い項目はメニューに出さない**（`SortField::is_available`）:
    発売日は DLsite だけが取得し、サイズはローカル本にしか無いため、サイト / 取り込み状況に
    よってメニューから消える。サイトを切り替えて現在の項目が使えなくなったら購入日に戻す
  - 同順位はタイトル昇順で決定的に並べる（従来の `ORDER BY ... , title ASC` と同じ）
  - 閲覧回数 / 閲覧時間 / 最終閲覧は `view_history` の集計（`view_history::view_stats`。
    reload で 1 クエリ）を使う
- **読書状態（未読 / 読書中 / 読了）**: 判定は core の `ReadingState::from_progress` **1 か所**で行い、
  本棚のカードバッジ・行の状態チップ・フィルタ・履歴画面・設定の冊数集計がすべてここを通る
  - **読了** = `finished_at` が立っている（リーダーが最終ページ到達でセット）、または
    `current_page >= total_pages`（`finished_at` を持たない旧データの救済）
  - **読書中** = 1 ページ目以降を読んだ（`current_page > 0`。1-indexed で、本を開いただけでは
    進捗行が作られないので未読のまま）
  - **未読** = 進捗が無い / `current_page == 0`
  - 色: 未読 = 黄（amber）/ **読書中 = 青（sky）** / 読了 = 緑（emerald）
  - フィルタは **未読 / 読書中 / 既読** の 3 択（未読に読書中は含めない）
  - ※ 設定画面の集計は以前 `current_page + 1 >= total_pages` で判定しており、**1 ページ早く
    読了になっていた**（デスクトップの進捗は 1-indexed のため）。共通判定に置き換えて解消した

- **カード操作**:
  - クリック: ローカル本はビューアー、リモート本はダウンロード
  - ダブルクリック: サイドバー（閉じている場合）を開いて本棚メニューを表示
  - 右クリック: コンテキストメニュー（開く / タグ編集 / 非表示にする /
    **閲覧回数**を最上部に表示）
  - キーボード: `←`/`h`・`→`/`l` で選択移動、`↑`/`k`・`↓`/`j`（j = 下、k = 上）、
    `Enter` で選択カードを開く。選択タイルは背景色 + 枠線でハイライトされ、
    選択に合わせてスクロールが追従する
- **ダウンロード / 取り込み**:
  - 技術書典・BOOTH の同期ボタン（専用スレッド + タイムアウト付き）
  - ダウンロードはバックグラウンドで実行され、進捗（%・ラベル）がカードに表示
  - PDF（レンダリング → webp）+ ZIP（画像セット）を .opfspack に変換
  - インポート後はイベント名補完・タグ生成（形態素解析 + Zenn タグマッチング）
- **表紙キャッシュ**: リモートの表紙は縮小 PNG（幅 288px）でキャッシュ。
  カード生成時にオリジナル画像を読み込むことで reload を高速化

### 閲覧履歴（History）

サイドバーの「閲覧履歴」（Lucide `history` アイコン）から開く。リーダーで開いた本が
`view_history`（1 回の閲覧 = 1 セッション）に記録されるので、それを **1 日 1 本**に集約して出す。

- **トップ**: `閲覧履歴` + 件数 + 期間フィルタ（**全項目** / 今日 / 今週 / 今月）+ サイトフィルタ
  （すべてのサイト / 履歴に含まれるサイト）+ カード形式 / リスト形式の切替（本棚と同じボタン）
  - **全項目**は期間とサイトの両方を解除する（本棚の「絞込中 ✕」と同じ位置づけ）
  - 今日 / 今週（**月曜始まり**）/ 今月はローカル日付で判定する
- **日単位でまとめる**: `2026年09月13日` の**日付バー**（背景色 = `primary` を薄く敷いた帯。
  ダークでは `muted` / `secondary` が同色なのでカードと区別するため）の下に、その日に読んだ本を
  並べる。同じ日に同じ本を何度読んでも **1 行に集約**する
- **1 件の表示は本棚と同じ情報**（閲覧時刻・閲覧時間は出さない）:
  表紙 + タイトル + **イベント名 or 購入日**（`shelf_event_text`。技術書典はイベント名、
  BOOTH / FANZA / DLsite は購入日、紐づく本棚アイテムが無ければ「イベント不明」）+
  サークル / 作者 + 進捗（`3 / 120ページ`）+ 読了 / 未読 + お気に入りハート + **タグ列**
  - カード形式は本棚のカードと同じ表紙比率（`cover_h = card_width * 0.75`、幅は窓幅から列数を
    計算）で、表紙の左上に読了 / 未読バッジ、右上にお気に入りハートを重ねる。タグは本棚と
    同じ 6 件折りたたみ + 「+n」/「閉じる」
  - リスト形式は**本棚の行と同じ 4 列構成**にする:
    表紙(200x133 固定) / **情報列(320px 固定** = `LIST_INFO_W`: タイトル・イベント名 or 購入日・
    サークル/作者チップ・進捗・読了/未読 + ♡) / **タグ列(行幅の 20%** = `LIST_TAGS_W_RATIO`。
    折りたたみ数は幅から計算 = `list_tags_visible_count`) / 残り（本棚は関連書籍カルーセル。
    履歴では出さないので空ける）。表紙は本棚と同じ 200x133 の枠（`LIST_COVER_W` /
    `LIST_COVER_MIN_H`、比率を保って収める）を共有する
  - サークル / 作者は**本棚と同じチップ**（値 + 右端のハートで `favorite_entities` をトグル）
  - **表紙の解決順も本棚と同じ**: サイトのサムネイルキャッシュ
    （`thumbnails/{site_id}_{database_id}_448.png`、`load_cached_cover`）→ pack の表紙
    （`load_cover_image`）→ プレースホルダ。カードの表紙枠は `cover_h = card_width * 0.75` で
    角丸（`rounded_t_lg`）・余白は `secondary`、リスト行の表紙枠は 200x133 固定で**角丸なし・
    余白は `muted`**（本棚の行と同じ）
  - タグは本棚と同じ挙動: 文字クリックで絞り込み（OR 条件。「全項目」/ ESC で解除）、
    ハートでタグのお気に入り、並びは 選択中 → お気に入り → 集計数の多い順 → 名前順
    （`TagOrder` を本棚と共用。チップ描画も `BookshelfView::render_tag_chips` を呼ぶ）。
    **タグ編集（✎）だけは履歴に出さない**（本棚のインラインエディタが本棚ビューの状態に
    紐づくため。依頼により今回は不要）
- **キーボード操作**（本棚と同じ）: `→`/`l`・`←`/`h`・`↓`/`j`・`↑`/`k` で選択移動
  （カード形式は列数ぶんの移動、リスト形式は ±1）、`Enter` で選択中の本を開く、
  `ESC` で絞り込み解除（期間 / サイト / タグ）。選択中のカード / 行は背景色 + 枠線で
  ハイライトし、選択した本が入る日付セクションへスクロールを寄せる
- **操作**: クリックでリーダーを開く（本棚と同じ `OpenReader` アクション）、
  ハートでお気に入りをトグル（`books` と、紐づく `bookshelf_items` の両方を更新）
- **時刻の扱い**: `view_history` の時刻は `CURRENT_TIMESTAMP`（= **UTC**）なので、
  `view_history::list_daily` が**ローカル時刻に直してから**日付でまとめる
  （UTC で日を切ると日本時間の朝が前日に入る）。日をまたいだセッションは開始時刻の日に属する
- **対象**: ローカルの本（リーダーで開ける本 = `books`）だけ。本棚と同じ**所有者フィルタ**
  （`owned_book_ids`）を通すので、アカウントを切り替えると他アカウントの履歴は出ない
- **表示モードの保存**: `history.view_mode`（settings）に card / list を保存する
- **再読み込み**: ナビゲーションで履歴へ切り替えたときに読み直す（読書直後の新しいセッションが
  反映される）

### 付箋（ページ単位のメモ）

- **DB**: `page_notes`（`id` / `book_id` / `content_id` / `page`（1-indexed）/ `memo` /
  `spread_side`（"left" / "right" / NULL）/ `is_active` / `created_at` / `updated_at`）。
  `book_id + content_id + page` で一意 = **1 ページ 1 件**。時刻は DB が UTC で入れる
  （`view_history` と同じ扱い。表示はローカルに直す）
  - **付箋の ON / OFF はメモとは別**（`is_active`）。外してもメモは残り、付け直すとメモが
    戻る（誤操作でメモを失わない）。`noted_pages` / 一覧は `is_active = 1` だけを返す
  - `is_active` は後から足した列なので、既存 DB 向けに `pragma_table_info` で確認してから
    `ALTER TABLE ... ADD COLUMN` する（マイグレーションファイルは作らない）
  - `content_id` を含むので、複数コンテンツ（本編 / 別冊）でもページ番号が衝突しない
  - リーダー用に「付箋が付いているページ（0-indexed）の集合」を返す `noted_pages` を持つ
- **付ける**: ビューアのページ画像の**上端**（右寄せ）の付箋アイコン → ダイアログ
  （「このページに付箋を付けました」+ メモ入力 + OK）。開くと既存のメモが読み込まれて編集に
  なる（見開き側は既存の値を優先して失わない）
  - アイコンは**しおり（リボン）型**（Lucide `bookmark`。ISC）で、**ON / OFF とも同じ形**。
    **枠のみで背景を置かず**、未付箋は半透明の灰色、**付箋ありは青系**（0x2563eb）に変える
    - **上辺の線はアセット側で描いていない**（`bookmark.svg` は左右の縦線だけ。Lucide の字形を
      `viewBox` で詰めたうえで上辺を外している）。画像の上端に置いても上辺が線として出ず、
      かつ `deferred` では画像のクリップが効かないため、はみ出しも起きない
    - 付箋ありは**中を半透明の青で塗る**（同じ形の塗り `bookmark-filled.svg` を 0.35 の
      不透明度で重ねる。上辺に線を出さないよう塗りはストロークなし）
    - 一辺は `NOTE_ICON_SIZE`（28px）で、ボタン / アイコン / 単一表示の位置計算で共有する
  - **置き場所は「実際に描かれている画像」の上端・右端**。単一表示は contain で中央寄せになる
    ので、ページ送りナビと同じ矩形計算（`img_left/img_top/img_w/img_h`）で画像の右上に合わせる
    （Scroll / Spread はページ枠の上端・右端）
  - **付箋ありのアイコンを押すと解除**（メモは残る。付け直すとメモが戻る）。未付箋はダイアログ
    を開いてメモを付ける
    - ダイアログを開くと**メモ入力欄にフォーカスが当たる**ので、そのまま打ち込める。
      入力中にビューアがキーボード操作のためフォーカスを**取り戻さない**ようにしている
      （`ImageViewer::set_note_dialog_open`。取り戻すとメモが打ち込めない）
    - 入力欄で **Enter を押すと OK**（保存して閉じる。`InputEvent::PressEnter` を購読）
  - **表示 / 非表示はトップバー・ボトムドックと同じ条件**（`overlay_visible && !zoomed`）に
    揃える（ページ送りを続けてバーが隠れると一緒に消え、戻すと出る）
  - **z-order は最前面**（`deferred` で描画だけ最後に回す）。トップバーの戻る領域やページ送りの
    ナビ帯より上でクリックを受け、付箋を押してもページ送り / 戻るは起きない
  - アイコンは単一表示 / 見開き / スクロール / 読み込み中のすべてで出す
    （ページの同一性は画像の有無に依存しない）
  - 見開きでは `spread_pages()` の左右から `spread_side` を決めて保存する
- **付箋画面**（サイドバーの「付箋」/ Lucide `sticky-note` アイコン、ISC。閲覧履歴の下）:
  `page_notes` を **追加が新しい順** に並べる。行は本棚のリスト形式と同じ 4 列
  - 1 列目: **付箋を付けたページの画像**（リーダーと同じ `load_thumb` の縮小経路。200x133 の枠）
  - 2 列目（320px 固定）: タイトル / イベント名 or 購入日 / サークル・作者チップ / 進捗 /
    読了・読書中・未読 + ♡ / **メモ** / **付箋登録日**（UTC 保存なので `local_date_label` で
    ローカル日付に直す）
  - 3 列目（行幅 20%）: タグ（本棚と同じチップ + ハート + 「+n」折りたたみ。文字クリックで
    絞り込み、ESC か「全項目」ボタンで解除）
  - 4 列目: **メモ**（タグ列の右。残り幅いっぱいに広げる）+ 右端に **✎**（タグ編集ボタンと
    同じ丸ボタン）。✎ を押すと**行の中がそのまま入力欄 + OK に置き換わる**（ダイアログは
    出さない。編集中はメモ本体と ✎ は隠れる）。**Enter か OK で保存 / ESC でキャンセル**
    （付箋の ON/OFF・登録日・見開き側は保持）
  - 5 列目: **「本を見る」**（矢印なし・行の高さいっぱいの塗りボタン。そのページ・
    その見開き側でビューアを開く）
  - **カルーセルは出さない**
- **「本を見る →」の復元**: `ReaderView::for_book_at` が `reading_progress` ではなく付箋の
  ページ（1-indexed）を使い、`spread_side` があるときは**見開きモードにして左右を合わせる**
  （見開きの左右は `spread_pages()` を見て、狙った側に来なければ 1 ページ戻す）

### リーダー（画像ビューアー）

本棚の本をクリックすると、ページ単位の画像ビューアーが開きます。

#### 表示モード

| モード | 説明 |
|---|---|
| 単一（Single） | 1 ページ表示。左右端 10% のクリックで前後ページへ |
| 見開き（Spread） | 2 ページを 1 枚の画像として表示。両ページが揃うまで表示しない（アトミック表示） |
| スクロール（Scroll） | 全ページを縦に連続表示。スクロール位置が現在ページに連動 |

- モードはサイト設定として永続化（`viewer.mode.{site}`）
- 綴じ方向（左綴じ / 右綴じ）は見開き専用設定（`viewer.page_turn`）

#### ズームとパン

- **ダブルクリック**: 2 倍 → 6 倍 → 解除（3 段階サイクル）
- **ホイール**: ズーム / 縮小（1.0 倍で解除）
- **ドラッグ**: 拡大中に画像を移動（パン）。可動範囲は「拡大後の画像サイズ −
  ビューポート」から正確に計算されるため、画像の隅まで移動できる
- **慣性**: マウスを離した後も速度に応じて滑らかに減速しながら移動
  （Google マップ風）。移動中の位置は補間され、開始時のジャンプもない
- 拡大中はトップ / ボトムメニューと左右のページ送りナビを非表示

#### ショートカット（トップメニュー → ショートカット）

| キー | 動作 |
|---|---|
| `→` / `l` | 次ページ（右綴じでは反転） |
| `←` / `h` | 前ページ（右綴じでは反転） |
| `shift+→` / `shift+←` | 見開きで 1 ページずらす |
| `↑` / `k` / `backspace` | 本棚に戻る |
| `esc` | メニュー表示 / パネルを閉じる（トグル） |
| ダブルクリック | 拡大（2 倍 → 6 倍 → 解除） |

#### ページ読み込みの最適化（性能）

- **デコード**: webp は **libwebp（C 実装）で直接 RGBA デコード**。
  image クレートの webp デコーダー（1000px で 1 秒以上）と比べて数十 ms に短縮
- **pack キャッシュ**: .opfspack のバイト列を OnceLock で 1 回だけ読み込む
- **キー導出のキャッシュ**: 暗号化 pack の PBKDF2（100k イテレーション）を
  1 回だけ実行（`derived_pack_key` + `read_entry_with_key`）
- **プリロード**: 現在ページ ±2 をバックグラウンドで並列ロード
- **保持キャッシュ**: 一度デコードしたページを直近 30 ページ保持
  （ページを戻っても再デコードしない）
- **ロード中フラグ**: 同一ページの二重ロードを防止
- **読み込み待ち**: スピナー表示（「読込中…」テキストは出さない）

#### 読書進捗と閲覧履歴

- ページ移動のたびに `reading_progress` を保存（1-indexed。最終ページ = total）。
  状態（未読 / 読書中 / 読了）は `ReadingState::from_progress` で判定する（上記参照）
- 最終ページ到達で `finished_at`（読了日時）をセット（一度セットすると維持）
- ビューアーを開いた時・閉じた時に**閲覧履歴**（`view_history`）を記録
  - 開始時刻と終了時刻を 1 セッションとして保存
  - 操作のたびに `ended_at` を更新するため、途中でアプリを落としても
    最後に操作した時刻まで記録される
- 本棚のカードの進捗表示（`current / total ページ`）はビューアーから戻った際に
  軽量更新（全件 reload はしない）

### チェックリスト（Checklist）

- チェック状態・メモ・価格・購入済みフラグ
- 試し読み: `product_sample_pages` の base64 画像をビューアーで表示

### 設定（Settings）

- アカウント: 技術書典ログイン / Google ログイン

## 認証とクラウド

### 技術書典

- サイトへ直接ログイン（GraphQL `UserLoginMutation`、XSRF-TOKEN ヘッダー）
- セッションは keyring（macOS キーチェーン）に保存
- 本棚同期・チェックリスト同期・お気に入り・試し読み

### Google / Google Drive

- OAuth 2.0 Desktop フロー（PKCE + ループバック `127.0.0.1:38387`）
- トークンは keyring に保存。401 時は自動リフレッシュ
- **同期フォルダ**: My Drive 直下の `thundoku-shelf/` フォルダ（Web 版の
  appdata ではなく、ユーザー可視のフォルダで Web 版とファイルを共有する）
  - フォルダ ID は初回同期時に作成し、`app_settings["drive.sync.folder_id"]` に保存
- **ファイル名**: `{bookId}.opfspack`（パック ID がそのままファイル名になる）。
  `appProperties: { app: "thundoku-shelf", packId }` を付与
- **双方向同期**: Drive 側の `md5Checksum` と `drive_sync_state.md5` を比較し、
  差異があるファイルだけダウンロード / アップロード
- **競合時のルール**: Drive 側を優先取得。ローカルの旧 pack は
  `packs/{packId}.conflict-local.opfspack` に退避（以後同期対象外）。
  削除は両方向とも伝播しない
- 暗号化 pack は Google の `sub` で復号（未ログインならログイン誘導）

### Zenn タグ

- 起動時に 1 回、プロセス内キャッシュで取得（タイムアウト付き）
- 実装タグマッチング（`zenn_tag_metadata`）に使用

## データの復元

**DB は「どのサイトのどのデータか（属性）」を保持し、「本の中身（ページ画像）」は
`.opfspack` パックにのみ存在する**、という関係。

### DB が保持するもの（属性・参照）

| データ | 内容 |
|---|---|
| サイト / 商品 | `books.site_id`、`books.tbf_product_id`、`bookshelf_items.site_id` / `database_id` |
| 再取得元 | `bookshelf_items.download_url`、`file_name` |
| メタ / 進捗 / 履歴 | タイトル・作者・サークル・タグ・読書進捗・閲覧履歴・ページ毎視聴（全 DB テーブル） |
| 参照 | `books.opfs_path`、`document_images.opfs_path` / `pack_entry_path`（どのパックの何ページか） |
| 一部画像 | 本棚の表紙サムネ（`thumbnail_data`）・試し読み（`image_data`）は base64 で DB に有る |

### DB が保持しないもの

- **本のページ画像** — `document_images` は width / height / mime / file_size / `pack_entry_path` のみで、
  **バイト列は無い**。画像は `.opfspack` パックにだけ存在。

### 復元シナリオ（DB 無事を前提）

| シナリオ | できること |
|---|---|
| DB + パック両方無事 | 完全復元 |
| DB だけ無事、パック消失 | メタ・進捗・属性は復元。ページ画像はパックが必要 → ① Drive からパック再取得（`drive.sync.enabled` 連動でバックアップ済み）② or サイトから再ダウンロード（`download_url` / `tbf_product_id` が DB に有る。ただしログインセッション（keyring）が要る） |
| パックだけ無事、DB 消失 | パックは「名前の無い画像の山」。DB を Drive バックアップ（`thundoku-backup.json`）から復元すればパックと再リンク |

> まとめ: **属性（どこ・何・どこから取るか）は DB、中身（画像）はパック。**
> パックが Drive にバックアップされていれば、DB さえ無事なら復元可能。

## 注意点（実装メモ）

- **ビューアーの進捗は 1-indexed**。DB の `reading_progress.current_page` は
  1 始まり（最終ページ = total_pages）。0 は未読扱い（表示上は 1 に補正）
- **イベント名補完は DB に書き込まない**（reload のたびに 315 件 × UPDATE が
  走り数百秒もかかるため、メモリ上で毎回補完する）
- **表紙キャッシュは縮小 PNG**。オリジナルサイズのキャッシュが残っていると
  reload が遅くなる（`thumbnails/` を削除すれば再取得される）
- `.opfspack` の読み込みはパックバイト列を 1 回だけ読み込んでキャッシュ。
  ディスク I/O は初回のみ
- ダウンロード / 同期 / 表紙取得はすべて専用スレッドで実行（UI をブロックしない）
- グリッドの仮想化により、315 件のカードで「スクロール中に全カードを再構築」
  する処理は行われない。フィルタ結果（`filtered`）はキャッシュされ、変更時のみ
  再計算
- マイグレーションは `crates/core/migrations/0001_init.sql` で管理されるが、
  追加のテーブル（`view_history`）はマイグレーションファイルを作らず、
  `migrate()` 内の冪等な DDL（IF NOT EXISTS）で適用される

- [x] **PDF の並列取り込みで稀にクラッシュする（修正済み）**
  - **原因（確定）**: **PDFium の同時利用そのものがスレッドセーフではない**。
    PDFium はプロセスで 1 つのライブラリ状態（フォントキャッシュ等）を共有し、
    `pdfium-render` の `thread_safe` feature は `unsafe impl Send/Sync for Pdfium` を
    足すだけ（**ロックはしない。呼び出し側の責任**）。
    当時の記録は「1 つの `PdfDocument` を 8 スレッドで共有」としていたが、実際の Windows 経路は
    **逐次ループ**、非 Windows の mupdf 経路も**スレッドごとに `Document::from_bytes`** しており、
    **ドキュメントを分けても再現する**（＝共有が原因ではなく PDFium 自体の同時利用が原因）
  - **再現（実測 / Windows / pdfium-render 0.9.3）**:
    - テキスト入りの 1 ページ PDF を 8 スレッド × 5 回で同時レンダリング → **3/3 で
      `STATUS_ACCESS_VIOLATION` (0xc0000005)、約 2 秒**（フォントキャッシュの競合）
    - リポジトリのフィクスチャ PDF を 8 スレッドで同時レンダリング →
      **`STATUS_STACK_BUFFER_OVERRUN` (0xc0000409)、数秒**
    - 四角形だけの PDF（フォント無し）や **WebP 並列エンコードは落ちない** →
      エンコーダは無関係で、**フォントを使う描画**が引き金
  - **採用した方針**: PDFium を使う区間（`pdfium_instance()` の初期化を含む）を
    `static PDFIUM_LOCK: Mutex<()>` で**直列化**する（`crates/core/src/import/pdf.rs`）。
    1 冊の中の描画は元々このループが逐次なので**単冊の速度は変わらない**（並行に複数冊を
    取り込むときだけ待ち合う）。非 Windows の mupdf 経路は `thread_local` コンテキストで
    スレッドごとに独立しているため**変更しない**（並列のまま）
  - **回帰テスト**: `crates/core/tests/import.rs::pdf_rendering_is_safe_from_multiple_threads`
    （テキスト入り PDF を 8 スレッド × 5 回。修正前はこのテストでプロセスが落ちていた）
  - **検証**: 回帰テスト **10/10 パス**（修正前は 3/3 クラッシュ）、フィクスチャ PDF の
    8 並列ストレス OK、`cargo test -p thundoku-core --test import`（並列実行）を **2 回とも
    34 passed**（修正前は約 1/8 で異常終了）

- [ ] **メモリ使用量の調査・削減（実測 約 6,000MB）**
  - [x] **調査（済み。主因は 2 つ）**
    - **(A) リーク（修正済み）**: `ImageViewer.self_handle` に強参照の自己循環があり、
      さらに `ReaderView::for_book` が `App::on_action` の**アプリ寿命 listener** に強い
      `Entity<ReaderView>` を渡していた（解除 API なし）。本を閉じてもビューアーごと
      解放されず、**開いた本ごとにデコード済みページ・サムネ・loader・pack バイト列が累積**する。
      → 両方 `WeakEntity` に変更。回帰テスト
      `image_viewer::tests::viewer_is_dropped_when_no_strong_handle_remains` /
      `views::reader::tests::reader_is_dropped_when_closed` を追加（修正前は両方 fail）
    - **(B) スクロールモードの全ページ保持（修正済み）**: `ImageViewer.images` は
      **ページ数長**の `Vec<Option<Arc<RenderImage>>>` で、Scroll では開いた時点で
      **全 index を `ensure_loaded`** し、スクロールしても解放していなかった。
      → **バイト予算 `SCROLL_CACHE_BUDGET_BYTES`（既定 384MiB）**を導入し、表示中ページの
      前後だけを保持（`trim_scroll_cache`）。外れたページは `Arc<RenderImage>` を落とし、
      **`Window::drop_image` で GPU の sprite atlas からも解放**する（従来はアプリから一度も
      呼んでおらず window 寿命まで残っていた）。開いたときも全ページではなく前後だけを読む。
      スクロールで可視になったページは render 側で `ensure_loaded` する
  - **実測（実 DB のページ寸法から計算）**: 1 ページ平均 **16MiB**（RGBA = w×h×4）。
    最大の本（192 ページ / 最大 2894×4093）で **5,631MiB**（≒ 観測値 6,000MB）。
    全 2,167 ページを同時に持つと 36.5GiB。デコード瞬間は libwebp のバッファ + コピーで 8×w×h
  - **残（B) の対策案**: バイト予算（例 384MiB）で表示中ページの前後のみ保持し、外れたら
    `Window::drop_image`（現在アプリから呼んでいない＝GPU の sprite atlas も window 寿命まで残る）
    で解放する。ただし Scroll 中に可視ページを `ensure_loaded` する経路が無いため
    併せて追加が必要で、高速スクロール時に一瞬「読み込み中」になるトレードオフがある
  - [x] **お気に入り自動ダウンロードの同時数制限（実装済み）**: 全お気に入りを一斉に
    ダウンロードしていたのを、**同時 2 件まで**に制限し、残りは待ち行列に積んで 1 件終わるごとに
