# アプリ機能情報

> **AI 向けの詳細設計仕様書は `docs/spec/README.md`（索引）**を参照。実装を別言語へ移植する／Web 版に戻すための、数値・定数・アルゴリズムまで書いたリファレンス。

Thundoku Shelf Desktop は、技術書典・BOOTH・FANZA同人・DLsite で購入した本の閲覧を目的とした
デスクトップアプリケーション（macOS / Windows）です。Web 版
（https://thundoku-shelf-staging.megablacklabel.workers.dev/）の機能をローカルで
再現し、追加でデスクトップ固有の機能を備えています。

- 技術: Rust + GPUI（zed の GUI フレームワーク）+ gpui-component
- ストレージ: SQLite（ローカルファイル）+ .opfspack（画像アーカイブ）
- 依存: `mise` でツールチェーン管理（`mise run <task>`）

## 起動（単一インスタンス）

同時に起動できるアプリは 1 つだけ。2 個目の起動はウィンドウを開かずに終了します
（多重起動すると DB・パック・ダウンロード先を共有してしまい、二重取り込みや
Google OAuth のループバックポート（`127.0.0.1:38387`）の取り合いが起きるため）。

- **仕組み**: config ディレクトリ（`dirs::config_dir()/thundoku-shelf/instance.lock`）の
  ロックファイルを OS のファイルロックで排他する。Unix は `flock` / Windows は
  `LockFileEx` で、どちらも `std::fs::File::try_lock` が吸収するため
  プラットフォーム分岐は無い（`thundoku_core::single_instance::InstanceGuard`）
- **ロックファイルの場所**: データ保存先（設定で変更可能）ではなく config ディレクトリに
  置く。保存先を変更しても「同時に動くアプリは 1 つ」を保つため
- **クラッシュ復帰**: ロックはプロセスに紐づくため、強制終了でも OS が解放する。
  古いロックが残って起動できなくなることはない（ロックファイル自体は残る）
- **2 個目の挙動**: 外部からは静かに終了する（`exit 0`）。痕跡はログに残る
  （Windows は `%TEMP%\thundoku-shelf\thundoku.log` に追記。ログファイルは追記式で
  開くため、2 個目の追記が起動中インスタンスの書き込みに上書きされない。
  増え続けないよう、起動時に 4MB を超えていたら捨てる）。既存ウィンドウの前面化はしない
- **フォールバック**: ガードを取得できない場合（config ディレクトリが解決できない、
  ロックファイルが開けない等）は起動を止めずに続行する
- **初期表示**: どのサイト（技術書典 / BOOTH / FANZA同人 / DLsite）にもログインしていなければ、
  本棚ではなく**説明画面**を開く。本が 1 冊も入らない空の本棚より、各ストアのログイン手順が
  書かれた説明画面のほうが入口として機能するため。**Google はアカウント連携用で
  本の供給元（サイト）ではない**ので、それだけのログインでは本棚を初期表示にしない
  （＝サイトに 1 つでもログイン済みなら従来どおり本棚）。判定はサイト別のログインフラグ
  （起動時のセッション復元直後の値）で行う（`any_site_logged_in`）

## 主な画面

ウィンドウ上部はタイトルバー（gpui-kit の `TitleBar`）。`TitleBar::window_options()` は透過
タイトルバー + `app_owns_titlebar_drag` を指定する（＝タイトルバーはアプリが描く契約）ため、
描かないと信号機（閉じる / 最小化 / 最大化）が下のヘッダーに重なって押せなくなり、ウィンドウを
ドラッグする領域も無くなる。左側（信号機の右 80 px から）にウィンドウ名を出す。Windows は
自前のタイトルバー（`win_title_bar`）で、同じ位置に名前と操作ボタンを置く。

### サイドバー

- **選択状態の表示**: いまどの画面に居るかをサイドバーで示す。選択中の行は
  **塗りつぶし**（下地 = `primary`、アイコン / ラベル = `primary_foreground`、ラベルは太字）、
  非選択の行はアイコンもラベルも `muted_foreground`（下地なし）。ホバーの下地は `muted` で、
  選択の塗りつぶしとは別の色にする。
  - 以前は選択の印が下地（`secondary`）だけで、**アイコンだけの幅では見分けがつかなかった**
    （ホバーの下地と同じ色だったため余計に紛らわしかった）。文字色だけを `primary` にする案も、
    ダークテーマでは `primary`（≈白）と `muted_foreground`（実測 rgb(163,163,163)）の差が
    出るものの、実際には `Icon` が親の文字色を継承しないため色が付かなかった
    （`sidebar_icon_color` でアイコンへ直接渡している）
  - レポート / 設定も選択状態を持つ（`NavTarget::Report` / `Settings`）。テーマ切替と
    アカウントは画面ではなく操作なので選択状態を持たない
  - 本棚のサイト別サブメニュー（すべての本 / 技術書典 / BOOTH / FANZA同人 / DLsite）は
    下地 `secondary` + 文字 `primary` の弱い強調にして、本体の行（塗りつぶし）と区別する
  - 見た目の決定は `sidebar_row_style`（純粋関数）1 か所。テスト
    `sidebar_row_style_marks_the_selected_row` が選択 / 非選択の色を検証する
- **ロゴ（説明画面への入口）**: タイルの地色で状態を示す。**説明画面を開いているときだけ
  `primary`**（グリフは `primary_foreground`）、それ以外は `muted`（グリフは
  `muted_foreground`）。ロゴは常に `primary` で塗ってあったため、サイドバーから「説明画面を
  開いている」ことが分からなかった（他の行の塗りつぶしとも揃う）。決定は
  `sidebar_logo_background` / `sidebar_logo_glyph_color`。テスト
  `sidebar_logo_tile_marks_the_about_view` が両状態の色を検証する
  - 実測（ダークテーマ）: 非選択のタイル = rgb(38,38,38) / 選択中のタイル = rgb(250,250,250)

### 本棚（Bookshelf）

- **表示モード**: カードグリッド / リスト（視点切替ボタン）。**選択した形式は保存され、
  次に開いたときも同じ形式で表示する**（設定キー `bookshelf.view_mode`。未設定はカード）
- **グリッド / リストの仮想化**: GPUI の `List` による行単位の仮想表示。画面に見えている
  行だけを構築するため、数百件のカード / 行でもスクロールが軽い
  - リストの行は仮想化リストが `max-content` で測るため、行の幅を `w_full()` で明示する
    （明示しないとタグ列 = 行幅の 20% が内容なりに広がり、タグが折り返さず行が伸びない）
- **絞り込み中のスクロール位置**: 絞り込み（タグ / イベント / サークル / 作者 / 既読 / 検索）を
  適用・解除しても位置を失わない。解除すると**絞り込む前の位置**に戻る。
  件数が変わると GPUI の `ListState::reset` でスクロールのアンカーが捨てられる（＝先頭に戻る）
  ため、位置を「先頭からの割合」で控えて差し替え後に指し直す
  （`set_list_count_keeping_scroll`。カード / リスト表示で別々のリスト状態を持つので両方に適用）
- **リスト表示の行**: 4 列（`表紙(200x133 固定)` / `情報列(320px 固定)` /
  `タグ情報エリア(行幅の 20%)` / `関連書籍カルーセル(残り幅いっぱい)`）。
  情報列は タイトル / 購入日 / サークル・作者 / ページ数 / 状態 の縦並び
  - 表紙も情報列も**固定サイズ**なので、行の高さが内容（タグの折返し等）で変わっても
    テキストの開始 X が全行で揃う（旧: 表紙が行の高さに追従して幅が変わり、行ごとにずれていた）
  - **未読 / 読んでいる途中 / 既読 / ダウンロード済み / お気に入り**はサムネイルに重ねず、
    **ページ数の下**に出す。文字タグは「未読 / 読んでいる途中 / 既読」だけ（四角い `Tag`。
    読んでいる途中は `TagVariant::Info` = 青系）。「ダウンロード済み / 未ダウンロード」
    「お気に入り」は文字だと長くて行が変な折り返しになるため、**アイコン**で出す
    （`HardDrive` / `Cloud` / `HeartFilled`・`Heart`、16px・tooltip で意味を補う）。色は
    **行の背景に合わせてテーマで変える共有パレット `StatusIconPalette`**（ライト / ダーク）から
    取り、行の背景（`muted`、選択中は `secondary`）に対して **4.5:1** を下回らない
    （旧: ライトは `#059669` / `#b45309` / `#db2777` / `muted_foreground` のままで
    2.99〜4.35:1、16px の細いアイコンが沈んでいた。`status_icons_are_readable_on_list_rows`
    で固定）。閲覧履歴の**リスト行**のハートも同じパレットを共有する。
    お気に入りは**登録 / 未登録の両方**を出し、未登録は控えめな輪郭ハートにする。
    お気に入りアイコンは**クリックでトグル**する（`bookshelf_items` + `books` を更新。
    行クリックへ伝播させないのでビューアー / ダウンロードは走らない）
  - **タグ情報エリア**: タグ（サークル / 作者チップと同じチップ）を**行幅の約 20%**に収め、
    入りきらなければその中で折り返す。折り返し行は `content_start()` で**上詰め**にする
    （既定の `align-content: stretch` だと行が列の高さいっぱいに伸び、タグが無い / 少ない本では
    編集ボタンが縦中央に落ちて他の列と頭が揃わない）
  - タグは**表示エリア（タグ列）の幅から入る個数を計算**して出し、入りきらない分は「+n」チップに
    畳む。個数の固定上限は持たない（窓が広いほど多く出る）。計算は「タグ名の実測幅
    （GPUI のテキスト計測）+ チップの装飾」をタグ列の幅に詰め、折り返し 4 行
    （`LIST_TAG_MAX_ROWS` = 表紙の高さ 133px ÷ チップ 1 行 ≈ 29px）を上限にする
    - 実測（「タグ01」形式のタグ 20 件・リスト表示）: 窓 700px = 1 件 / 1000px = 7 件 /
      1400px = 11 件 / 1920px = 15 件。このとき行の高さはタグ無しの行と同じ 150px のまま
      （4 行を超えないので伸びない）。※テストはサイドバー無しの窓なので、サイドバー
      （`SIDEBAR_W`）を引く計算より実際の行は広い = ここに出る数は下限
    - チップ 1 個ぶんの幅すら入らない極端に狭い窓では 1 件だけ出し、「+n」は次の行へ
      折り返す（行が 1 行ぶん伸びる。個数を 0 にして「+n」だけの行にしない）
  - タグの折り返しで行の高さが伸びると、固定サイズの表紙 / カルーセルとの間に大きな余白が
    できるため、行の高さがタグ列に支配されないようにする。「+n」をクリックすると
    **全タグを表示**して列（= 行）が伸び、チップが「閉じる」に変わって折りたたみへ戻せる
    （展開状態は行ごとに view が保持。`tag-toggle-<database_id>`）
  - **タグの並び順**（カード / リスト / お気に入りタグ一覧）: **選択中 → お気に入り → 集計数
    （そのタグを持つカード数）の多い順 → 名前順**。集計は `reload` 時にカードのタグから数える
    （`count_tag_usage`。追加の SQL は無し）ので、タグの追加・削除や取り込みで集計が変わると
    次の reload で並びが変わる。
    お気に入りはチップのハートを押した瞬間に並び替わる（`TagOrder` を描画ごとに作り直す。
    reload は不要）。ハートの塗り分けも同じ `TagOrder` を見る。折りたたみ時もお気に入りタグは
    先頭なので畳まれない
    - **選択中のタグも先頭に出す**（折りたたみ中に隠れないように）。選択を解除すると集計数 /
      名前順の元の位置に戻る。フィルタで絞り込んだタグは結果の本すべてに出るタグなので、
      畳まれて見えなくなるのを防ぐ（`selected_tag_stays_visible_when_collapsed`）
  - **カード（グリッド）のタグ**: `CARD_TAGS_COLLAPSED_MAX`（6 件）で折りたたみ、残りは「+n」チップ
    （リストと同じ `tag-toggle-<database_id>` / 展開状態を共用。展開中のラベルは「閉じる」）。
    カードは**行の高さを共有する**ため、1 冊のタグ数で行全体が間延びする。幅 190px のカード
    （`p_3` の内容幅 166px）で実測: タグ無し = 296.5px、6 件 = チップ 3 行・+90.0px、
    20 件を展開 = 10 行・+295.0px（タグ名は「タグ01」= 2 文字 + 2 桁）
    - 実データ（`book_tags` 276 件）ではタグ名の 77% が 4 文字以下（チップ 2 個 / 行）、
      1 冊あたり最大 14 タグ。上限が無いとカードごとに 1〜10 行までばらつくのが元の崩れ
    - 長いタグ名（「長いタグ名前01」= 6 文字 + 2 桁）だけの本では 6 件で 6 行・+149.0px まで
      伸びる。行をこれ以上伸ばしたくない場合は上限を下げる（`CARD_TAGS_COLLAPSED_MAX`）
  - **並び替えの負荷**（実測・debug ビルド）: 集計は 1000 冊 × 30 タグ（30,000 件）で 33.7ms、
    1 フレーム分（可視 25 冊 × 30 タグ）の並び替えは 1.06ms。並び替えは**可視カードだけ**なので、
    お気に入りの付け外し（`TagOrder` の作り直し + 並び替え）で reload は走らない
  - **関連書籍カルーセル**（タグ情報エリアの右側）: 同一サークル → 同一作者の順に最大 5 件。
    ツールチップで作品名、クリックでビューアー（ローカル本）/ ダウンロード（未取得）。
    関連が無い本にはカルーセル自体を出さない
  - カルーセルのサムネイルは**カルーセル列の幅を 2 等分**して埋める（アイテム幅 =
    列幅 ÷ 2）。大きさの上限はリストの表紙と同じ（実測: 1484px 幅で 196x130 ≒ 表紙
    200x133）。列幅が広いときは上限に当たり、3 枚目が少し覗く（旧: 固定 162px で
    3.5 枚ぶんの幅に 162px を並べていた）。3:2 の枠に比率を保って収める = 切り抜きしない
  - カルーセルは `gpui-kit` の `Carousel`。`CarouselState` は行ごとに view が保持し、
    `reload` で関連件数が変わったときだけ作り直す
  - 前へ / 次へは**自前の四角いバー**（高さはサムネイルと同じ、幅 26px、tooltip は
    日本語の「前へ / 次へ」）。組み込みの `CarouselPrevious` / `CarouselNext` は円形で、
    しかもコンテンツ枠の**外側**に絶対配置されるため next がリストの `overflow_hidden` で
    切れて見えなかった。バーは通常の flex 要素として並べる
  - バーは移動できる向きだけホバーで色が変わる（`theme.secondary` はダークで背景の
    `muted` と同色 15% のため変化が見えない。`views::hover_bg` のモード別グレーを使う）。
    移動できない向きは **Button の disabled と同じ薄さ**（アイコン
    `muted_foreground.opacity(0.5)` + 背景 `muted.opacity(0.4)`）にしてホバー / `cursor_pointer`
    を付けない = **無効表示**
  - バーは**移動できない向きでもクリックハンドラを必ず登録**して `stop_propagation` する
    （登録が無いと移動不可のバーのクリックが行へ抜けてビューアーが開く）。
    `select_next` / `select_previous` は移動できる向きだけ呼ぶ
  - スナップの速さはテーマの `motion.spring_move` を上書きする（カルーセルに個別設定が無いため
    `main.rs` で指定: 既定 280ms / 減衰 0.85 → **120ms / 0.9**）。実測で静止までの時間が
    256ms → 136ms になる
  - 行が高くなったとき（タグ展開）は、カルーセルも表紙と同じく**上揃え**にする
  - 行のクリックは本文（タイトル等）と同じ経路（ローカル本は開く / 未取得は取り込む）。
    カルーセル内のクリックは `stop_propagation` で行クリックへ伝播させない
- **フィルタ**:
  - サイト（すべての本 / 技術書典 / BOOTH / FANZA同人 / DLsite。ログイン中のストアの行だけ出る）
  - 検索（タイトル・サークル名・著者名）
  - タグ（OR 条件）、イベント、読了状態（未読 / 読んでいる途中 / 既読 / お気に入り）
  - **イベントフィルタは技術書典の本棚のときだけ出す**（それ以外のサイトでは概念が無いため
    非表示。以前は BOOTH 以外で出ていた）
- **並び替え（ソート）**: ツールバー 2 段目の右グループ、**表示切替ボタンの左隣**の
  「並び替え」ボタン（Popover）。現在の項目と方向をボタンに常時表示する
  （例: 「並び替え: 購入日 新しい順」）
  - **項目**（単一選択）: 購入日（既定）/ 発売日 / タイトル / 最終閲覧日 / 閲覧回数 /
    閲覧時間 / サイズ
  - **方向**（単一選択）は項目に合った言葉にする（日付 = 新しい順 / 古い順、
    回数 = 多い順 / 少ない順、サイズ = 大きい順 / 小さい順、タイトル = A→Z / Z→A）
  - **選択 UI は gpui-kit の `Radio`（`component::radio::Radio`）**を使う（自前で丸を描かない）。
    項目・方向それぞれが単一選択のラジオで、選択中は塗りつぶし・未選択は枠のみ
  - 選んだらメニューを閉じる。**選択済みの項目をもう一度押しても何も変わらない**（ラジオの
    意味論どおり。方向は「方向」セクションで選ぶ）。「既定に戻す」で購入日（新しい順）に戻る
  - **日付は正規化して比較する**（`date_sort_key`）。サイトごとに形式が違うため
    （技術書典 = RFC3339 / BOOTH・DLsite = `YYYY/MM/DD` / FANZA = `YYYY年MM月DD日`）、
    生の文字列では全サイト横断で時系列に並ばない。値なしは方向に関係なく末尾
  - **データが無い項目はメニューに出さない**（`SortField::is_available`）:
    発売日は DLsite だけが取得し、サイズはローカル本にしか無いため、サイト / 取り込み状況に
    よってメニューから消える。サイトを切り替えて現在の項目が使えなくなったら購入日に戻す
  - 同順位はタイトル昇順で決定的に並べる（従来の `ORDER BY ... , title ASC` と同じ）
  - 閲覧回数 / 閲覧時間 / 最終閲覧は `view_history` の集計（`view_history::view_stats`。
    reload で 1 クエリ）を使う
- **読書状態（未読 / 読んでいる途中 / 読了）**: 判定は core の `ReadingState::from_progress` **1 か所**で行い、
  本棚のカードバッジ・行の状態チップ・フィルタ・履歴画面・設定の冊数集計がすべてここを通る
  - **読了** = `finished_at` が立っている（リーダーが最終ページ到達でセット）、または
    `current_page >= total_pages`（`finished_at` を持たない旧データの救済）
  - **読んでいる途中** = 1 ページ目以降を読んだ（`current_page > 0`。1-indexed で、本を開いただけでは
    進捗行が作られないので未読のまま）
  - **未読** = 進捗が無い / `current_page == 0`
  - 色: 未読 = 黄（amber）/ **読んでいる途中 = 青（sky）** / 読了 = 緑（emerald）
  - フィルタは **未読 / 読んでいる途中 / 既読** の 3 択（未読に読んでいる途中は含めない）
  - 表示ラベルは「未読 / 読んでいる途中 / 読了」（リストのタグとフィルタだけ「既読」）。
    以前は「読書中」だったが、何を指すのか伝わりにくいため「読んでいる途中」に変えた
    （他の長いタグは折り返しを避けてアイコンにしているが、この語は状態の意味を優先する）
  - ※ 設定画面の集計は以前 `current_page + 1 >= total_pages` で判定しており、**1 ページ早く
    読了になっていた**（デスクトップの進捗は 1-indexed のため）。共通判定に置き換えて解消した

- **カード操作**:
  - クリック: ローカル本はビューアー、リモート本はダウンロード。**そのカードが選択状態になる**
  - ダブルクリック: サイドバー（閉じている場合）を開いて本棚メニューを表示
  - 右クリック: そのカードを選択してコンテキストメニュー（開く / **ダウンロード中止** /
    タグ編集 / 非表示にする / **閲覧回数**を最上部に表示）
  - キーボード: `←`/`h`・`→`/`l` で選択移動、`↑`/`k`・`↓`/`j`（j = 下、k = 上）、
    `Enter` で選択カードを開く、`Backspace` で選択中の本の**ダウンロード中止**。
    選択タイルは背景色 + 枠線でハイライトされ、選択に合わせてスクロールが追従する
- **ダウンロード / 取り込み**:
  - 技術書典・BOOTH・FANZA同人・DLsite の同期ボタン（専用スレッド + タイムアウト付き）
  - **サイトのログイン直後は、そのサイトを自動で同期する**: ログインの完了イベント
    （`BoothLoginDone` など）で同期を要求し（`AppState.login_sync_requested` にサイト id を
    置く）、`Workspace` の監視タスクが**1 回だけ**消費して `BookshelfView::sync_site` を呼ぶ。
    ログイン直後の本棚は購入済みの一覧が空で、手動で「同期」を押させたくないため。
    起動時のセッション復元では完了イベントが発火しないので、**再起動のたびに同期は走らない**。
    Google のログインでは同期しない（本の供給元ではない）。手動の「同期」ボタン
    （`sync_all`）はサイト絞り込み中ならそのサイトだけ、絞り込み無しなら 4 サイトすべてを回す
    （同じ `sync_site` を使う。サイト id の一覧は `SYNC_SITE_IDS`）
  - ダウンロードはバックグラウンドで実行され、進捗（%・ラベル）がカードに表示
  - **取り込みには Google ログインが要る**: pack の鍵（v3 の PRK）は Google アカウントごとに
    作るため、未ログインでは取り込めない（**平文 pack を作らない** = fail-closed。セキュリティ
    評価 F03）。ダウンロードを**始める前**に判定し、未ログインなら
    `本を取り込むには Google にログインしてください（本はアカウントごとの鍵で暗号化されます）`
    と通知して Google の認証モーダルを開く（`require_import_login`）。入口は本棚のカード /
    行 / 関連サムネイルのクリック、ダウンロード確認の「はい」、コンテキストメニューの「再取得」。
    お気に入りの自動ダウンロードは利用者が要求した操作ではないので、**通知だけ出して見送り**、
    モーダルは開かず待ち行列にも積まない。**取り込み済みの本の閲覧にログインは要らない**
  - **2 GiB を超える本は、ダウンロードを始める前に確認する**: ストアが申告するファイルサイズ
    （FANZA の詳細 API・DLsite の作品ページ「ファイル容量」）を使い、2 GiB を超えるときだけ
    「この本は 2 GB を超えています（ファイル容量: 約 X GB）／取得する・やめる」を出す
    （pack の上限は 10 GiB なので扱えない線ではない。**転送に時間とディスクを使う**ことを
    先に伝えるための確認）。**サイズが分からないときは出さない**
    （誤って止めない）。お気に入りの自動ダウンロードはモーダルを出さず通知のみ。一度確認した本は
    同じセッションで二度聞かない（`crates/core/src/store_size.rs`）
  - **本ごとに「Drive バックアップ対象外」を選べる**: 大きい本は右クリックメニューの
  「バックアップ対象外にする」で、Drive への同期（アップロード）から外せる（**終了時の
  アップロードでも上がらない**）。pack が 1 GiB を超える本は取り込み時に**自動で**対象外に
  なる（同メニューで戻せる）。未ダウンロードの本は対象外にできない（落とす必要があるため）
- **「パスフレーズ必須」を選べる**: 設定 →「本の鍵」→「必須にする」で、Google Drive の
  `thundoku-keys.json` から「Google アカウントで解ける形」を消す（**Google ログインだけでは
  本の鍵を復元できない**。Drive の鍵ファイルと `sub` を奪われても本は復号できない）。
  代償として、他の端末・Web 版ではパスフレーズ入力が必須になり、**忘れると復元できない**。
  解除は同じ場所から（解錠ダイアログでパスフレーズを確認してから戻す）
- **そもそも大きすぎる入力は先に断る**: 取り込み元ファイルは 2 GiB（`MAX_IMPORT_SOURCE_BYTES`。
    読む前に判定）、外側 ZIP は件数 10000 と展開後合計、PDF は 9000 ページを展開・描画の前に見る
    （セキュリティ評価 F06）
  - PDF（レンダリング → webp）+ ZIP（画像セット）を .opfspack に変換。
    大きい pack でもメモリを食い潰さないよう、**組み立てはファイルへ直接**（一時ファイル →
    rename）行い、pack 全体のハッシュはファイルを順に読んで計算する
  - インポート後はイベント名補完・タグ生成（形態素解析 + Zenn タグマッチング）
  - **取り込み中はビューアーを開かない**: 別の本（ダウンロード済み）をクリックしても開かず、
    「ダウンロード中です。終わってから開いてください」と通知する（取り込みの書き込みと
    ビューアーの読み込みを重ねない）。右クリックメニューの「開く」も同条件で無効。
    クリックした本自体が取り込み中なら、終わったら開くように予約する。未ダウンロード本の
    扱いはクリック元で違う（**行・関連サムネイル**は「取り込みますか？」の確認を挟む /
    **カードと Enter** はそのまま取り込む）
  - **取り込み内容の確認**（形式やコンテンツが複数のときだけ）: 選択肢リストだけがスクロールし
    （高さは行数ぶん。上限は 360 px とウィンドウ高の半分の小さい方）、項目が増えてもフッターの
    ボタンが画面外に出ない。バツは置かない（worker が回答を待っているため）。表示中はビューアーを
    開かず、開いていれば閉じる（モーダルがビューアーの下の層に描かれて操作できなくなるのを避ける）
  - **ダウンロード中止**: 進行中の本だけ、コンテキストメニューの「ダウンロード中止」または
    `Backspace` で中止できる（確認ダイアログ → 「中止する」）。中止は**転送そのものを中断**し、
    途中まで取得した内容は捨てて取り込まない（進捗リングは即座に消え、「ダウンロードを中止しました」
    と通知する）。取り込み（レンダリング）が始まった後は中断できないため、実行中＝`Downloading` の
    本だけメニュー項目が有効になる。取り込み確認モーダル待ちのときは、中止でその待ちも解放する
    （worker が取り込みへ進まない）。`Backspace` の対象は「選択中の本」で、選択が実行中の本で
   なければ走っているダウンロードが 1 件だけのときにそれを対象にする（複数走っていて選択も
   別の本なら何もしない。対象を選んでから中止する）
  - **未ダウンロード本のタグ（FANZA）**: FANZA のタグ（ジャンル）は作品ページの HTML にしか
    無く **1 件 = 1 リクエスト**なので、全件まとめて叩くと DMM 側の bot 判定で同期ごと
    失敗しうる。同期が成功したときに **1 回 20 件まで・直列・300 ms 間隔**で取得し、
    取得済みの印（`bookshelf_items.tags_fetched`）が立った作品は次回の対象から外す
    （何回かの同期で埋まる）。失敗した作品は印を立てず次回に再試行し、セッション切れ
    （401/403）はその場で打ち切る。ヘッダーの「タグ取得」トグル（`tag.fetch.enabled`）が
    OFF のときは取りに行かない。取得できたら「FANZA の未ダウンロードのタグ情報を N 件
    取得しました（残り M 件が未取得）」と**保護つき通知**で知らせる（ダウンロード済みの本は
    取り込み時にタグを取っているので対象外。DLsite は一覧 API で同期時に取れる）
- **表紙キャッシュ（遅延読み込み）**: リモートの表紙は縮小 PNG（幅 448px）でキャッシュ。
  **`reload` では表紙を読まず**（stat だけで「ローカルに元があるか」を判定）、
  **可視になった行から順に**デコードする（可視 + 前後 24 件を先読み。描画の最後に
  `apply_cover_requests` がまとめて処理する）。デコード結果は LRU（予算 96 MiB）に持ち、
  **`reload` をまたいで再利用**する。予算を超えたぶんは可視を除いて古い順に落とし、
  `window.drop_image` で GPU のテクスチャごと解放する（内蔵 GPU ではテクスチャも
  システム RAM のため。以前は 612 件ぶん = 実測 507 MB を常駐させ、`reload` のたびに
  デコードし直していた）。
  pack の表紙は `PackFileReader` で**ヘッダ + インデックス + 表紙エントリだけ**を読み
  （pack 全体を読まない）、448px に縮小して持つ。再ダウンロード・削除では該当の
  キャッシュを捨てる。関連書籍カルーセルの表紙も可視のうちに読み込み対象へ入れる

### お気に入り（Favorites）

サイドバーの「お気に入り」（`HeartFilled` アイコン。**本棚の下**、閲覧履歴の上）から開く。
**本棚と同じ画面**を使い、お気に入りだけを出す（検索・サイト絞り込み・並び替え・カード /
リストの切替は本棚と共通で、表示形式の設定も共有する）。

- 見出しは「お気に入り」+ 注意書き「お気に入りにした本は、Google にログイン中のとき、
  同期時に未ダウンロードだと自動でダウンロードされます」（`FAVORITES_NOTE`）
- **お気に入りの絞り込みボタンは出さない**（画面そのものが絞り込みなので、「全項目」で
  解除してもお気に入りは外れない）。未読 / 読んでいる途中 / 既読 / イベント /
  お気に入りタグの絞り込みは本棚と同じように使える
  - サイト絞り込み中に出す「お気に入りタグ」は、**そのサイトに存在するタグの集合を
    reload / フィルタ変更時にキャッシュ**して作る（`rebuild_filtered` →
    `refresh_site_favorite_tags`）。**描画中は DB を引かない**
- **本棚のサイトスコープ（サイドバーの本棚の下のサブメニュー）は適用しない**:
  お気に入り画面は**すべてのサイト**のお気に入りを出す。サイトスコープは本棚の閲覧スコープで、
  お気に入り画面にはサイトを出す見出しが無いため、適用すると「お気に入りが 0 件」になった
  理由が画面から分からなくなる
- サイドバーの**未読数は本棚のときだけ**出すので、この画面では出ない
- **「タグ取得」と「同期」は出さない**（本棚側の操作なので）。表示切替（カード / リスト）と
  並び替え、検索、各絞り込みは本棚と同じに使える
- **自動ダウンロード**: お気に入りの未ダウンロード本は、起動時（本棚の初回描画）と、
  BOOTH / FANZA / DLsite / 技術書典の**同期が終わったとき**に自動で落とす（同時 2 件まで =
  `MAX_AUTO_DOWNLOADS`。すでに実行中 / 待ち行列にある本は積み直さない）。**Google 未ログイン
  では取り込めない**（鍵はアカウントごと。セキュリティ評価 F03）ので、通知だけ出して見送る
  （起動しただけで勝手に認証モーダルを開かない）

### 閲覧履歴（History）

サイドバーの「閲覧履歴」（Lucide `history` アイコン）から開く。リーダーで開いた本が
`view_history`（1 回の閲覧 = 1 セッション）に記録されるので、それを **1 日 1 本**に集約して出す。

- **トップ**: `閲覧履歴` + 期間フィルタ（**全項目** / 今日 / 今週 / 今月）+ サイトフィルタ
  （すべてのサイト / 履歴に含まれるサイト）+ カード形式 / リスト形式の切替（本棚と同じボタン）
  - **全項目**は期間とサイトの両方を解除する（本棚の「絞込中 ✕」と同じ位置づけ）
  - 今日 / 今週（**月曜始まり**）/ 今月はローカル日付で判定する
- **日単位でまとめる**: `2026年09月13日` の**日付バー**（背景色 = `primary` を薄く敷いた帯。
  ダークでは `muted` / `secondary` が同色なのでカードと区別するため）の下に、その日に読んだ本を
  並べる。同じ日に同じ本を何度読んでも **1 行に集約**する
- **1 件の表示は本棚と同じ情報**（閲覧時刻・閲覧時間は出さない）:
  表紙 + タイトル + **イベント名 or 購入日**（`shelf_event_text`。技術書典はイベント名、
  BOOTH / FANZA / DLsite は購入日、紐づく本棚アイテムが無ければ「イベント不明」）+
  サークル / 作者 + 進捗（`3 / 120ページ`）+ 読了 / 未読 + お気に入りハート + **タグ列**
  - カード形式は本棚のカードと同じ表紙比率（`cover_h = card_width * 0.75`、幅は窓幅から列数を
    計算）で、表紙の**枠の内側**にオーバーレイを重ねる: 左上 = 読了 / 未読バッジ、
    右上 = お気に入り、右下 = ダウンロード済み（履歴の本はすべてローカル本なので常に「済み」）。
    右上 / 右下は**本棚のカードと共有の `CoverBadge` / `cover_badge()`**（表紙の上で読める配色・
    状態で形が変わる・ホバー説明）。タグは本棚と同じ 6 件折りたたみ + 「+n」/「閉じる」
  - リスト形式は**本棚の行と同じ 4 列構成**にする:
    表紙(200x133 固定) / **情報列(320px 固定** = `LIST_INFO_W`: タイトル・イベント名 or 購入日・
    サークル/作者チップ・進捗・読了/未読 + ♡) / **タグ列(行幅の 20%** = `LIST_TAGS_W_RATIO`。
    折りたたみ数は幅から計算 = `list_tags_visible_count`) / 残り（本棚は関連書籍カルーセル。
    履歴では出さないので空ける）。表紙は本棚と同じ 200x133 の枠（`LIST_COVER_W` /
    `LIST_COVER_MIN_H`、比率を保って収める）を共有する。情報列の**お気に入りハート**は
    本棚の行の状態アイコンと同じ共有パレット `StatusIconPalette` から色を取り（丸の地色は
    `background`）、ホバーで「お気に入り（クリックで解除）/ お気に入りにする」を出す
  - サークル / 作者は**本棚と同じチップ**（値 + 右端のハートで `favorite_entities` をトグル）
  - **表紙の解決順も本棚と同じ**: サイトのサムネイルキャッシュ
    （`thumbnails/{site_id}_{database_id}_448.png`、`load_cached_cover`）→ pack の表紙
    （`load_cover_image`）→ プレースホルダ。カードの表紙枠は `cover_h = card_width * 0.75` で
    角丸（`rounded_t_lg`）・余白は `secondary`、リスト行の表紙枠は 200x133 固定で**角丸なし・
    余白は `muted`**（本棚の行と同じ）
  - タグは本棚と同じ挙動: 文字クリックで絞り込み（OR 条件。「全項目」/ ESC で解除）、
    ハートでタグのお気に入り、並びは 選択中 → お気に入り → 集計数の多い順 → 名前順
    （`TagOrder` を本棚と共用。チップ描画も `BookshelfView::render_tag_chips` を呼ぶ）。
    **タグ編集（✎）だけは履歴に出さない**（本棚のインラインエディタが本棚ビューの状態に
    紐づくため。依頼により今回は不要）
- **キーボード操作**（本棚と同じ）: `→`/`l`・`←`/`h`・`↓`/`j`・`↑`/`k` で選択移動
  （カード形式は列数ぶんの移動、リスト形式は ±1）、`Enter` で選択中の本を開く、
  `ESC` で絞り込み解除（期間 / サイト / タグ）。選択中のカード / 行は背景色 + 枠線で
  ハイライトし、選択した本の行が見える位置へ `ListState::scroll_to_reveal_item` で寄せる
- **仮想化**: 一覧は本棚と同じ `gpui_kit::list` + `ListState` で、**可視行だけ**を構築する。
  行は「日付バー」と「その日の本（カードは 1 行に列数ぶん / リストは 1 行 1 件）」で、
  列数はウィンドウ幅から決まるため幅が変わったときだけ組み直す。行の高さは一律のヒント
  （カードは表紙の 3/4 + 情報、リストは表紙枠 + 余白）を与え、描いた行は実測値に置き換わる
  （全行を計測する `measure_all` を使うと初回フレームで全行を構築してしまうため使わない）
- **操作**: クリックでリーダーを開く（本棚と同じ `OpenReader` アクション）、
  ハートでお気に入りをトグル（`books` と、紐づく `bookshelf_items` の両方を更新）
- **時刻の扱い**: `view_history` の時刻は `CURRENT_TIMESTAMP`（= **UTC**）なので、
  `view_history::list_daily` が**ローカル時刻に直してから**日付でまとめる
  （UTC で日を切ると日本時間の朝が前日に入る）。日をまたいだセッションは開始時刻の日に属する
- **対象**: ローカルの本（リーダーで開ける本 = `books`）だけ。本棚と同じ**所有者フィルタ**
  （`owned_book_ids`）を通すので、アカウントを切り替えると他アカウントの履歴は出ない
- **表示モードの保存**: `history.view_mode`（settings）に card / list を保存する
- **再読み込み**: ナビゲーションで履歴へ切り替えたときに読み直す（読書直後の新しいセッションが
  反映される）

### 付箋（ページ単位のメモ）

- **DB**: `page_notes`（`id` / `book_id` / `content_id` / `page`（1-indexed）/ `memo` /
  `spread_side`（"left" / "right" / NULL）/ `is_active` / `created_at` / `updated_at`）。
  `book_id + content_id + page` で一意 = **1 ページ 1 件**。時刻は DB が UTC で入れる
  （`view_history` と同じ扱い。表示はローカルに直す）
  - メモ本文（`memo`）は**平文で保存しない**（keyring の DB 鍵で AES-256-GCM。セキュリティ評価
    F02。保存形式は `docs/spec/02-data-model.md` §1.11）。読み出しは復号し、復号できない値
    （鍵違い・改ざん）は**空のメモ**として扱う（暗号文は画面に出さない。付箋の ON / OFF・
    ページ・見開き側は残す）
  - **付箋の ON / OFF はメモとは別**（`is_active`）。外してもメモは残り、付け直すとメモが
    戻る（誤操作でメモを失わない）。`noted_pages` / 一覧は `is_active = 1` だけを返す
  - `is_active` は後から足した列なので、既存 DB 向けに `pragma_table_info` で確認してから
    `ALTER TABLE ... ADD COLUMN` する（マイグレーションファイルは作らない）
  - `content_id` を含むので、複数コンテンツ（本編 / 別冊）でもページ番号が衝突しない
  - リーダー用に「付箋が付いているページ（0-indexed）の集合」を返す `noted_pages` を持つ
- **付ける**: ビューアのページ画像の**上端**（右寄せ）の付箋アイコン → ダイアログ
  （「このページに付箋を付けました」+ メモ入力 + OK）。開くと既存のメモが読み込まれて編集に
  なる（見開き側は既存の値を優先して失わない）
  - アイコンは**しおり（リボン）型**（Lucide `bookmark`。ISC）で、**ON / OFF とも同じ形**。
    **枠のみで背景を置かず**、未付箋は半透明の灰色、**付箋ありは青系**（0x2563eb）に変える
    - **上辺の線はアセット側で描いていない**（`bookmark.svg` は左右の縦線だけ。Lucide の字形を
      `viewBox` で詰めたうえで上辺を外している）。画像の上端に置いても上辺が線として出ず、
      かつ `deferred` では画像のクリップが効かないため、はみ出しも起きない
    - 付箋ありは**中を半透明の青で塗る**（同じ形の塗り `bookmark-filled.svg` を 0.35 の
      不透明度で重ねる。上辺に線を出さないよう塗りはストロークなし）
    - 一辺は `NOTE_ICON_SIZE`（28px）で、ボタン / アイコン / 単一表示の位置計算で共有する
  - **置き場所は「実際に描かれている画像」の上端・右端**。単一表示は contain で中央寄せになる
    ので、ページ送りナビと同じ矩形計算（`img_left/img_top/img_w/img_h`）で画像の右上に合わせる
    （Scroll / Spread はページ枠の上端・右端）
  - **付箋ありのアイコンを押すと解除**（メモは残る。付け直すとメモが戻る）。未付箋はダイアログ
    を開いてメモを付ける
    - ダイアログを開くと**メモ入力欄にフォーカスが当たる**ので、そのまま打ち込める。
      入力中にビューアがキーボード操作のためフォーカスを**取り戻さない**ようにしている
      （`ImageViewer::set_note_dialog_open`。取り戻すとメモが打ち込めない）
    - 入力欄で **Enter を押すと OK**（保存して閉じる。`InputEvent::PressEnter` を購読）
  - **表示 / 非表示はトップバー・ボトムドックと同じ条件**（`overlay_visible && !zoomed`）に
    揃える（ページ送りを続けてバーが隠れると一緒に消え、戻すと出る）
  - **z-order は最前面**（`deferred` で描画だけ最後に回す）。トップバーの戻る領域やページ送りの
    ナビ帯より上でクリックを受け、付箋を押してもページ送り / 戻るは起きない
  - アイコンは単一表示 / 見開き / スクロール / 読み込み中のすべてで出す
    （ページの同一性は画像の有無に依存しない）
  - 見開きでは `spread_pages()` の左右から `spread_side` を決めて保存する
- **付箋画面**（サイドバーの「付箋」/ Lucide `sticky-note` アイコン、ISC。閲覧履歴の下）:
  `page_notes` を **追加が新しい順** に並べる。行は本棚のリスト形式と同じ **6 列**で、
  左から **表紙 / 情報 / タグ / 付箋ページ / メモ / 本を見る**
  - 1 列目: **本の表紙**（本棚のリストと同じ枠。サイトの表紙キャッシュ → pack の cover →
    プレースホルダの順に解決する）
  - 2 列目（320px 固定）: タイトル / イベント名 or 購入日 / サークル・作者チップ / 進捗 /
    読了・読んでいる途中・未読 + ♡ / **付箋登録日**（UTC 保存なので `local_date_label` で
    ローカル日付に直す）
  - 3 列目（行幅 20%）: タグ（本棚と同じチップ + ハート + 「+n」折りたたみ。文字クリックで
    絞り込み、ESC か「全項目」ボタンで解除）
  - 4 列目: **付箋を付けたページの画像**（リーダーと同じ `load_thumb` の縮小経路。表紙と同じ枠）
  - 5 列目: **メモ**（残り幅いっぱいに広げる）+ 右端に **✎**（タグ編集ボタンと
    同じ丸ボタン）。✎ を押すと**行の中がそのまま入力欄 + OK に置き換わる**（ダイアログは
    出さない。編集中はメモ本体と ✎ は隠れる）。**Enter か OK で保存 / ESC でキャンセル**
    （付箋の ON/OFF・登録日・見開き側は保持）
  - 6 列目: **「本を見る」**（矢印なし・行の高さいっぱいの塗りボタン。そのページ・
    その見開き側でビューアを開く）
  - **カルーセルは出さない**
  - 画像（本の表紙・付箋ページ）はどちらも**表示中の行だけ**背景でデコードし、
    **同じ LRU（64 件）を共有**する（上下限を超えた行はプレースホルダのまま）
- **「本を見る →」の復元**: `ReaderView::for_book_at` が `reading_progress` ではなく付箋の
  ページ（1-indexed）を使い、`spread_side` があるときは**見開きモードにして左右を合わせる**
  （見開きの左右は `spread_pages()` を見て、狙った側に来なければ 1 ページ戻す）

### リーダー（画像ビューアー）

本棚の本をクリックすると、ページ単位の画像ビューアーが開きます。

リーダーはウィンドウのタイトルバーの下から始まります（タイトルバーは表示中も残るので、
閉じる / 最小化 / 最大化が使えます）。上端は `workspace::TITLE_BAR_HEIGHT`（Windows 36 px /
非 Windows 34 px）で、画像のフィット計算も同じ値を引きます。

#### 表示モード

| モード | 説明 |
|---|---|
| 単一（Single） | 1 ページ表示。左右端 10% のクリックで前後ページへ |
| 見開き（Spread） | 2 ページを 1 枚の画像として表示。両ページが揃うまで表示しない（アトミック表示） |
| スクロール（Scroll） | 全ページを縦に連続表示。スクロール位置が現在ページに連動 |

- モードはサイト設定として永続化（`viewer.mode.{site}`）
- 綴じ方向（左綴じ / 右綴じ）は見開き専用設定。**既定はサイト単位**（`viewer.page_turn.{site}`。
  FANZA / DLsite は右綴じ、他は左綴じ）で、ビューアの「右綴じ / 左綴じ」ボタンで変えると
  **その本だけ**に保存される（`books.page_turn`）。同じサイトの別の本や、設定画面の
  サイト別設定は変わらない（本ごとの指定を消す UI は無い）

#### ホイールでのページ送り

- **ホイール 1 ノッチ = 表示モードに合った送り幅**。単一は 1 ページ、**見開きは 1 見開き
  （2 ページ）**進む / 戻る（1 ページ送りにすると綴じ位置が 1 枚ずつズレるため）。
  1 ページだけずらしたいときは `Shift` + 左右キー。`Ctrl` + ホイールは従来どおりズーム。
  スクロール（連続）モードと、ページ一覧などのパネル上では効かない
- トラックパッドのように細かいデルタが来る場合は、1 ノッチぶん（3 行）まで累積してから
  1 回だけ動かす（1 回のイベントで何ページもめくらない）
- **どちらの方向で次へ進むかは設定で選べる**: 設定 →「ビューア共通設定」→
  「ホイール 1 ノッチで 1 ページ送る向き」（`viewer.wheel_direction` = `down-to-next` /
  `up-to-next`）。既定は `down-to-next`（下スクロールで次へ）
  - Windows は `WM_MOUSEWHEEL` の正（ホイールを前方へ）が文書を先へ進める方向。macOS は
    AppKit がナチュラルスクロール設定を反映した delta を渡すため、どちらも「ユーザーに
    とっての下」がそのまま次へになる

#### ズームとパン

- **ダブルクリック**: 2 倍 → 6 倍 → 解除（3 段階サイクル）
- **Ctrl + ホイール**: ズーム / 縮小（1.0 倍で解除）
- **ドラッグ**: 拡大中に画像を移動（パン）。可動範囲は「拡大後の画像サイズ −
  ビューポート」から正確に計算されるため、画像の隅まで移動できる
- **慣性**: マウスを離した後も速度に応じて滑らかに減速しながら移動
  （Google マップ風）。移動中の位置は補間され、開始時のジャンプもない
- 拡大中はトップ / ボトムメニューと左右のページ送りナビを非表示

#### ショートカット（トップメニュー → ショートカット）

| キー | 動作 |
|---|---|
| `→` / `l` | 次ページ（右綴じでは反転） |
| `←` / `h` | 前ページ（右綴じでは反転） |
| `shift+→` / `shift+←` | 見開きで 1 ページずらす |
| `↑` / `k` / `backspace` | 本棚に戻る |
| `esc` | メニュー表示 / パネルを閉じる（トグル） |
| ダブルクリック | 拡大（2 倍 → 6 倍 → 解除） |

#### ページ読み込みの最適化（性能）

- **デコード**: webp は **libwebp（C 実装）で直接 RGBA デコード**。
  image クレートの webp デコーダー（1000px で 1 秒以上）と比べて数十 ms に短縮
- **pack キャッシュ**: .opfspack のバイト列を OnceLock で 1 回だけ読み込む
- **キー導出のキャッシュ**: 暗号化 pack の鍵導出（v3 は `HKDF(PRK, book_id)`）を
  1 回だけ実行（`derive_pack_key` + `read_entry_with_key`）
- **プリロード**: 現在ページ ±2 をバックグラウンドで並列ロード（**見開きは ±3**。
  表示が 2 ページ単位なので、次の見開きの 2 枚目まで先読みしないと送った直後に
  片方が未読のまま白い箱で描かれる）
- **保持キャッシュ**: 一度デコードしたページを直近 30 ページ保持
  （ページを戻っても再デコードしない）
- **ロード中フラグ**: 同一ページの二重ロードを防止
- **表示用の前縮小（モアレ対策）**: ページ画像は**表示に必要な幅**（ウィンドウ幅 ÷ 見開き枚数
  × scale factor × ズーム。`ImageViewer::update_display_target`）へ、**デコード直後に縮小してから**
  GPU に渡す（`PageLoader::load_for_display` → `downscale_for_display`）
  - 縮小は 2 段: 面積平均（`thumbnail`）で目標の 2 倍強まで落としてから `Lanczos3` で仕上げる
    （27MP のページにいきなり `Lanczos3` を 6 倍縮小でかけると 1 秒近くかかるため）
  - **理由**: GPUI には補間 / mipmap の指定が無く、フル解像度をそのまま渡すと実質 1 タップの
    サンプリングで縮小され、網点（スクリーントーン）がクロスハッチ状のモアレになって潰れる
    （実測: 4441x6213 のページを見開きで 690px 幅に描画したときに発生）。メモリも約 1/6
    （約 110MB/ページ → 約 16MB）になる
  - ズームやウィンドウ拡大で必要幅が増えたときは、**1.2 倍を超えて足りなくなったページだけ**
    読み直す（縮小方向と 1.2 倍以内の増加は読み直さない = ズームの端数で読み込み直さない）
  - ページ一覧のサムネイル（`load_thumb`）は 22 倍以上縮小することがあり枚数も多いため、
    速度優先で `Triangle` のまま（見る大きさの画像だけ高品質フィルタ）
- **読み込み待ち**: スピナー表示（「読込中…」テキストは出さない）

#### 読書進捗と閲覧履歴

- ページ移動のたびに `reading_progress` を保存（1-indexed。最終ページ = total）。
  状態（未読 / 読んでいる途中 / 読了）は `ReadingState::from_progress` で判定する（上記参照）
- 最終ページ到達で `finished_at`（読了日時）をセット（一度セットすると維持）
- ビューアーを開いた時・閉じた時に**閲覧履歴**（`view_history`）を記録
  - 開始時刻と終了時刻を 1 セッションとして保存
  - 開始時刻で `ended_at` を初期化し、ビューアーを閉じたときに現在時刻へ更新する
    （heartbeat 更新はしない。途中でアプリを落とすと `ended_at` は開始時刻のまま残る）
- 本棚のカードの進捗表示（`current / total ページ`）はビューアーから戻った際に
  軽量更新（全件 reload はしない）

### チェックリスト（Checklist）

サイドバーの「チェックリスト」とメニューの「チェックリスト」は **技術書典にログインしている
ときだけ**使える（同期も試し読みも技術書典のセッションが要るため）。サイドバーは行ごと隠し、
メニューは項目を無効にする（メニューの構成は変わらないほうが位置が安定するため）。

- イベント一覧（`tbf_events`）からサークルをチェックリストで管理
- チェック状態・メモ・価格・購入済みフラグ
- 試し読み: `product_sample_pages` の base64 画像をビューアーで表示
  - 画像は自サイトの **`/api/image/`** から取得する（本棚の TBF 表紙のフォールバックも同じ
    入口 = `TbfClient::download_site_image`）。本体（`/api/product-dlc/`）とは
    **別の許可リスト**にしてある（本体用を使うと画像が全部ブロックされて開けない）。
    取得中はその行の表紙に**進捗リング + %** を出し、ページごとの受信バイトで進む
    （`Content-Length` が無い画像はページ完了で進む）

### 設定（Settings）

設定値は画面に入ったとき（`reload`）に DB から読み、**描画中は DB を読まない**（カードは
保持している値を表示するだけ）。

- ビューア共通設定: ホイール 1 ノッチで 1 ページ送る向き（下スクロールで次へ / 上スクロールで次へ）
- アカウント: 技術書典ログイン / Google ログイン
- Google Drive 同期: 接続 / ドライブ同期トグル / 同期フォルダ表示 /
  「今すぐ同期」ボタン / 最終同期日時
  - 同期中は段階付きの進捗を出す: 取得中は `pack-1.opfspack を取得中（2/5・3.0 MB / 9.0 MB）`
    + 進捗バー、アップロード中は `pack-2.opfspack をアップロード中`、DB バックアップは
    `バックアップを作成中`（進み具合が分からない段階ではバーを出さない）
  - **「中止」**は同期中いつでも押せて、次の区切り（取得中はその場 / アップロードは次の
    ファイルの直前 / バックアップは書き出す前）で止まる。取り込み済みの本はそのまま残り、
    完了は通知で伝える（エラー表示にはしない）
- 外観: ライト / ダーク
  - ダークは面の階層をアプリ側で引き直す（`theme::apply_dark_surfaces`）: 背景（neutral-950）→
    カード・入力（neutral-800）→ 浮いた面（neutral-900 = 通知・ポップオーバー・ダイアログ）→
    縁（neutral-600 = `border` / `input`）。膜（`overlay`）は背景を 55% 暗くする。既定のダークは
    `popover` が背景と同色・`border` がカードやダイアログの面と同色で、通知やダイアログが
    背景に溶けていた
  - ライトは `theme::apply_light_surfaces` が膜を 50%（既定は 5% で、白い面が背景と同じ白のため
    膜も縁も効かず溶けていた）に、縁（`border` / `input`）を neutral-300 にする。面を背景より
    明るくする余地が無いため、膜と影で浮かせる
  - ダイアログ（起動時の復元確認 / 複数内容の取り込み / 終了時のアップロード確認 / ローカル
    データ削除 / ダウンロード中止）の面はテーマの「浮いた面」`popover`、縁は `border`、副ボタンは
    `dialog_button`（縁付き。`Button` の既定は塗りが面とほぼ同じ明るさで形が見えないため）。
    面を `background` のままにすると、ダークでは膜と影がほとんど効かず境界がヘアライン頼みに

## 認証とクラウド

### 技術書典

- サイトへ直接ログイン（GraphQL `UserLoginMutation`、XSRF-TOKEN ヘッダー）
- セッションは keyring にある鍵で暗号化して保存（`SessionVault`）。**保存期間は 7 日**で、
  それを過ぎたら起動時に破棄して再ログインを求める（旧版の keyring 保存値は起動時に
  一度だけ vault へ移行し、keyring から消す）
- ログアウトは①メモリ②端末の保存情報（vault / keyring）③サイト側④ログイン WebView の
  保存データを区別し、成功した範囲だけを知らせる（`docs/logout.md`）
- 本棚同期・チェックリスト同期・お気に入り・試し読み

### Google / Google Drive

- OAuth 2.0 Desktop フロー（PKCE + ループバック `127.0.0.1:38387`）
- トークンは keyring に保存。401 時は自動リフレッシュ
- **同期フォルダ**: My Drive 直下の `thundoku-shelf/` フォルダ（Web 版の
  appdata ではなく、ユーザー可視のフォルダで Web 版とファイルを共有する）
  - フォルダ ID は初回同期時に作成し、`app_settings["drive.sync.folder_id"]` に保存
- **ファイル名**: `{bookId}.opfspack`（パック ID がそのままファイル名になる）。
  `appProperties: { app: "thundoku-shelf", packId }` を付与
- **双方向同期**: Drive 側の `md5Checksum` と `drive_sync_state.md5` を比較し、
  差異があるファイルだけダウンロード / アップロード
- **競合時のルール**: Drive 側を優先取得。ローカルの旧 pack は
  `packs/{packId}.conflict-local.opfspack` に退避（以後同期対象外）。
  削除は両方向とも伝播しない
- 暗号化 pack はアカウントごとのルート鍵（v3 の PRK。keyring か Drive の `thundoku-keys.json` から解決。必要ならパスフレーズを尋ねる）で復号する。**鍵を用意できなければ平文として読まずに失敗**する（未ログインならログイン誘導）。旧形式（v2）の pack は開けないので、ストアから取り込み直す
- **取り込み（ダウンロード）には Google ログインが必要**（鍵をアカウントごとに作るため。未ログインでは取り込まず、ダウンロードを始める前にログインを促す — セキュリティ評価 F03）。**すでに取り込んだ本を読むのにログインは要らない**

### GitHub / レポート（Issue 投稿）

アプリから GitHub の Issue を立てる導線。**GitHub のログイン状態に関わらず**サイドバーの
「設定」の上に「レポート」を常に出す。

- **アプリは GitHub のトークンを一切取得・保存しない**。Issue を 1 つ作るためだけに
  `public_repo`（＝公開リポジトリへの書き込み）を利用者へ求めるのは権限が過大なので、
  OAuth Device Flow は廃止した（keyring のスロットも削除。`USER_GITHUB` は残っていない）
- **送信**: 「Issue を作成」で
  `https://github.com/{owner}/{repo}/issues/new?title=<enc>&body=<enc>` を**既定のブラウザー**で
  開く（ブラウザーを開く処理は Google ログインと同じ `google::open_browser`。Windows は
  `ShellExecuteW` で URL をそのままシェルへ渡す）。投稿そのものは利用者が GitHub の画面で行う
  （**未ログインでも投稿できる**）。本文は percent-encode する（空白は `%20`。`+` は本文の
  `+` と区別できないため使わない）
  - 本文が長すぎて URL に載らないとき（目安 8,000 文字 = `MAX_ISSUE_URL_CHARS`）は、
    **先に本文をクリップボードへコピー**してから素の `/issues/new` を開き、
    「本文をコピーしました」と通知する（URL とコピーの要否は core の `issue_link` が返す）
  - **labels は付けない**（一般利用者にラベルを付ける権限が無い）。テンプレートの `labels` も読まない
- **テンプレート**: `.github/ISSUE_TEMPLATE/*.yml`（issue form）を**匿名で**取得し、
  `name` / `title` / `body[]`（label / placeholder / required）を解釈して本文の下書きに
  展開する（`config.yml` は除外）。一覧は Contents API（匿名の枠は 1 時間 60 回）、本文は
  `raw.githubusercontent.com`（CDN。既定ブランチは `HEAD`）から取る
  - 取得に失敗しても**テンプレート無しで書ける**（画面に理由と「再取得」を出すだけで、
    レポート画面は壊さない）。1 ファイルが読めない / 大きすぎる / 解析できない場合は
    その 1 件だけ飛ばす
- **画像添付**: アプリからのアップロードは**行わない**（選択 UI も無い）。画面に「画像は GitHub の
  画面で添付してください」と明記して、利用者が GitHub の画面で添付する。以前は送信時に
  `POST https://uploads.github.com/user-attachments/assets` へ上げていたが、それには対象
  リポジトリへの write 権限（＝ `public_repo`）が必要で、権限を求める理由そのものだったため廃止した
- **投稿先**: `MegaBlackLabel/thundoku-shelf-app` に**固定**（画面に「このリポジトリの Issue に
  投稿します（変更できません）」と表示する）。宛先を利用者が差し替えられると、誘導された
  利用者に別のリポジトリへ文面を送らせる余地になるため
- **制約**: アプリ側では投稿の成否が分からない（通知は「作成画面を開いた」までを伝える）。
  テンプレート取得は匿名アクセスなので、共有 IP では 1 時間 60 回の API 枠に当たり得る
  （当たったら理由を出して「再取得」を促す）

### Zenn タグ

- 起動時に 1 回、プロセス内キャッシュで取得（タイムアウト付き）
- 実装タグマッチング（`zenn_tag_metadata`）に使用

## 通知（グローバル）

アプリ全体で共通の通知を使えます。表示は **gpui-kit の Notification**
（`gpui_kit::component::notification`）で、**ウィンドウ右上**に出て既定 5 秒で自動的に消えます
（マウスを乗せるとカウントダウンが止まる）。

- **表示**: `crate::app_state::set_toast_kind(cx, ToastKind::X, "メッセージ")`（`cx` は任意の
  ビューのコンテキスト）。生の `set_toast` は**クレート内に隠してある**（種別 / 自動消滅 /
  進行中の各フラグを更新しないため、直に呼ぶと前の通知の設定を引き継いでしまう。
  実際に Drive 同期の「同期完了」が消えずに残り続ける不具合になっていた）
- **保護つき通知**: `set_protected_notice` で出す通知は、**5 秒間（自動消滅と同じ）**は
  バックグラウンドの通知（進行中の通知・定期同期の完了通知）に上書きされない。トーストは
  1 つしか出せず後から出たものが上書きするため、タグ取得の完了のように「読んでほしい」
  通知で使う（エラー通知は保護中でも必ず出す）
- **種別**:
  - `ToastKind::Info` — 進捗・案内（「〜中です」「ログインしてから〜してください」など）
    - 既定は 5 秒で自動消滅。終了時のアップロード中だけは完了（アプリ終了）まで消えない
      （`AppState.toast_autohide`）
  - `ToastKind::Success` — 完了（「〜が完了しました」「〜件取得しました」「削除しました」など）
  - `ToastKind::Error` — 失敗（同期/取り込みエラー、開始できないとき）
  - 旧「赤い 1 行」「下部の 1 行」の自前表示は廃止した（`BookshelfView` の `toast` /
    `error` フィールドも削除）
- **ホスト**: `Workspace` が `Root::render_notification_layer(window, cx)` を描画し、
  メッセージを `window.push_notification((種別, メッセージ), cx)` に流す（世代番号で 1 回だけ。
  同じメッセージが重複して積まれない）
- ログアウト・同期完了・ダウンロード完了・展開完了などで使用
- 通知に置き換えたことで、本棚下部のメッセージ表示用スペース（下部パディング + 非表示
  ダイアログぶんの gap で **28px**）は廃止した（1 行でも多く本を表示するため。
  `grid_reaches_the_bottom_of_the_view` で回帰を防ぐ）

## データの復元

**DB は「どのサイトのどのデータか（属性）」を保持し、「本の中身（ページ画像）」は
`.opfspack` パックにのみ存在する**、という関係。

### DB が保持するもの（属性・参照）

| データ | 内容 |
|---|---|
| サイト / 商品 | `books.site_id`、`books.tbf_product_id`、`bookshelf_items.site_id` / `database_id` |
| 再取得元 | `bookshelf_items.download_url`、`file_name` |
| メタ / 進捗 / 履歴 | タイトル・作者・サークル・タグ・読書進捗・閲覧履歴・ページ毎視聴（全 DB テーブル） |
| 参照 | `books.opfs_path`、`document_images.opfs_path` / `pack_entry_path`（どのパックの何ページか） |
| 一部画像 | 本棚の表紙サムネ（`thumbnail_data`）・試し読み（`image_data`）は base64 で DB に有る |

### DB が保持しないもの

- **本のページ画像** — `document_images` は width / height / mime / file_size / `pack_entry_path` のみで、
  **バイト列は無い**。画像は `.opfspack` パックにだけ存在。

### 復元シナリオ（DB 無事を前提）

| シナリオ | できること |
|---|---|
| DB + パック両方無事 | 完全復元 |
| DB だけ無事、パック消失 | メタ・進捗・属性は復元。ページ画像はパックが必要 → ① Drive からパック再取得（`drive.sync.enabled` 連動でバックアップ済み）② or サイトから再ダウンロード（`download_url` / `tbf_product_id` が DB に有る。ただしログインセッション（7 日で失効する暗号化保存）が要る） |
| パックだけ無事、DB 消失 | パックは「名前の無い画像の山」。DB を Drive バックアップ（`thundoku-backup.json`）から復元すればパックと再リンク |

> まとめ: **属性（どこ・何・どこから取るか）は DB、中身（画像）はパック。**
> パックが Drive にバックアップされていれば、DB さえ無事なら復元可能。

## 注意点（実装メモ）

- **ビューアーの進捗は 1-indexed**。DB の `reading_progress.current_page` は
  1 始まり（最終ページ = total_pages）。0 は未読扱い（表示上は 1 に補正）
- **イベント名補完は DB に書き込まない**（reload のたびに 315 件 × UPDATE が
  走り数百秒もかかるため、メモリ上で毎回補完する）
- **表紙キャッシュは縮小 PNG**。オリジナルサイズのキャッシュが残っていると
  reload が遅くなる（`thumbnails/` を削除すれば再取得される）
- `.opfspack` の読み込みはパックバイト列を 1 回だけ読み込んでキャッシュ。
  ディスク I/O は初回のみ
- ダウンロード / 同期 / 表紙取得はすべて専用スレッドで実行（UI をブロックしない）
- グリッド / リストの仮想化により、315 件のカードで「スクロール中に全カード・全行を
  再構築」する処理は行われない。フィルタ結果（`filtered`）はキャッシュされ、変更時のみ
  再計算（描画は Card / List とも同じ `filtered` を見る）
- マイグレーションは `crates/core/migrations/0001_init.sql` で管理されるが、
  追加のテーブル（`view_history`）はマイグレーションファイルを作らず、
  `migrate()` 内の冪等な DDL（IF NOT EXISTS）で適用される
