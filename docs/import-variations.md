# 取り込みバリエーション対応（アイデアメモ）

ダウンロードするファイルの構成が増えてきたため、取り込み時の対応方針を検討中。
このドキュメントは現時点の**アイデアと検討メモ**（実装予定・確定事項ではない）。

## 現状（対応済み）

- `import_file`: `.pdf` / `.epub` / `.zip` を受け付ける
- `import_zip_bytes`: ZIP を展開して
  1. PDF が見つかれば **PDF のみ取り込み**（画像は無視）
  2. PDF が無ければ**画像セット**として取り込み（パス名ソート → ページ化）
- サブフォルダ・複数素材の混在は未対応

## 観測されているパターン

| # | パターン | 備考 |
|---|---|---|
| 1 | PDF のみ | 現状対応済み |
| 2 | 同じ内容の PDF と画像一式 | 現状 PDF 優先で画像は捨てられる |
| 3 | 表紙と裏表紙が画像、本文が PDF | 現状 PDF のみ取り込み（画像無視） |
| 4 | 圧縮されてない PDF（単体） | 現状対応済み |
| 5 | 複数のフォルダに入っている画像ファイル | パスソートで概ね動くがフォルダ意図は無視 |
| 6 | 表紙・裏表紙・本文が PDF + オマケ画像 | 現状オマケ画像は無視 |
| 7 | フォルダに画像ファイル群、吹き出し文字の有無パターン | 同一内容 2 セット（文字あり/なし） |
| 8 | 総集編でシリーズがフォルダごと | サブフォルダ = 1 冊として分冊したい |

## 検討中の対応方針

### 基本方針:「自動推定 → 迷ったときだけ確認」

- **明確な構成**（PDF のみ・画像のみ・表紙画像 + PDF 本文など、取り込み方法が一意に決まる）
  → **モーダルなしで自動取り込み**
- **曖昧な構成**（同一内容の素材が複数ある場合: PDF と画像の両方、吹き出し有無の 2 セットなど）
  → **選択モーダル**を表示。ただし：
  - 中身の**サマリー**を見せる（例:「本文 PDF 24p + 表紙/裏表紙画像 2 枚」「同一内容が 2 セット（文字入り / 文字なし）」）
  - **デフォルト選択済み**の選択肢を出す（確定は 1 クリック）
- 自動決定した場合も、取り込んだ構成を**トーストで明示**（例:「本文 PDF 20p + オマケ画像 3 枚で取り込みました」）
  - おかしいと思ったら**削除 → やり直し**（ローカル削除機能が既にあるため、修正コストは低い）

### 実装の下準備（検討段階）

1. **ZIP 構造解析**（共通ロジック）:
   - サブフォルダ単位のグループ化（総集編: フォルダ = 1 冊）
   - ファイル名ヒューリスティックで用途推定:
     - `cover*` / `back*` / `表紙` / `裏表紙` など → 表紙側の画像
     - `page*` / `img*` / 数字連番 → 本文画像
     - `*.pdf` → 本文（PDF レンダリング）
   - 「同一内容の複数候補」（PDF と画像、文字あり/なし）の検出
2. **ページ合成パイプライン**:
   - 表紙画像 →（PDF 本文のレンダリング）→ 裏表紙画像 → オマケ画像 の順に 1 冊へ
   - ビューアーがそのまま読める「ページ列」（`pages/page_0001.webp` 形式）に統一
3. **複数冊生成**（パターン 8）:
   - サブフォルダごとに 1 冊として生成（フォルダ名を書名候補に）

### UX 上の検討点

- 全部モーダルは「操作が毎回止まる」「中身を見ずに選ばせることになる」ため避けたい
- 「明確 → 自動」「曖昧 → 情報つき 1 クリック確認」がバランスが良い（現時点の見解）
- 自動取り込み時も構成をトーストで明示し、誤りは削除 → やり直しでリカバリ

## 補足: BOOTH ライブラリの「1 商品 2 ファイル」問題（2026-08-27 調査）

### 事実

- BOOTH のライブラリには**1 商品に複数ダウンロード**（PDF + 画像 ZIP 等）があるケースがある
- 現状の `booth.rs::parse_library` は各商品ブロックから **`data-href`（downloadables/{id}）を最初の 1 つだけ**抽出（`extract_download_url` の先頭一致 + ブロックを `start + 4000 文字` で切るため、2 個目以降のボタンは拾えない）
- DB 実績: BOOTH 系の本は全て `file_name = *.pdf`・`source_type = pdf` → **PDF 側を取得していた**（BOOTH の HTML で PDF が先頭に並んでいるため）
- **2 個目のファイル（画像 ZIP 等）は永久に無視される**

### 課題

パターン 2（同じ内容の PDF と画像一式）は「取り込み時の選択」だけでは解決しない。
**同期（どのファイルを取得するか）の段階で選択/列挙が必要**。

### 検討中の対応案

1. **ファイルごとに 1 アイテムとして列挙**:
   BOOTH のダウンロードボタンをファイルごとに別アイテムとして登録（タイトル例: 「大佐の趣味 (PDF)」「大佐の趣味 (画像)」）→ ユーザーがダウンロードの対象を選ぶ
2. **優先順位を明示**: どちらかを常に優先（現在 PDF 優先。画像優先に変えるかは用途次第）
3. **複数ファイルが検出されたときだけ確認モーダル**（「自動推定 → 迷ったときだけ確認」方針と連動）
   - 「1 商品 = 複数ファイル」の検出はパーサーの HTML 解析（同一ブロック内の data-href を複数列挙できるようにする）が前提

### 注意

- どの案でも**パーサーの強化**（ブロック内の data-href を全列挙 + ファイル名抽出）が先
- ファイル名（extract_file_name が `min-w-0 break-words` から拾う）は複数ファイル時にもっとらえるか要確認
