# Google アカウント切替の設計

> ⚠️ **このファイルは旧仕様です。**
> 冒頭の「基本モデル」〜「対象外」（§1〜§6・解決する不整合 表）と、
> 中盤の「~~補足: 未ログイン時（サブキー無し pack）の対応~~」（Plan B 案）は**不採用**です。
> **実装は「# 改訂版（採用）」と「# 実装上の確定事項（おすすめ方針）」のみ参照**してください
> （旧仕様・補足の記述は無視。誤って読まないこと）。

Google ログインするユーザを変更したときの挙動を定める。
**「1 つの Google アカウント = 1 つのアプリデータ・プロファイル」** を基本モデルとし、
アカウントとデータの対応を明確にして、中途半端な不一致状態を作らない。

> 背景: `books` などのローカルデータは Google アカウントに紐づかない（TBF/BOOTH 由来）。
> 一方で暗号化 Pack は `sub`（Google ユーザ識別子）に紐づくため、アカウントを替えると
> 読めない本が生じる。その不整合を「検知 → 2 択（初期化 / ログアウト）」で畳む。

## 基本モデル

- **同じ Google アカウント（同 `sub`）** = 同じプロファイル → 何も起きない。
- **別の Google アカウント（別 `sub`）** = 別プロファイル →
  **初期化（作り直す）** か **ログアウト（戻す）** の 2 択。
- **中途半端な状態**（別アカウントでログイン中 + 前アカウントのデータが残る）は**作らない**。

## 1. 検知（ログイン直後）

- Drive セットアップ時の `sub` を `app_settings["drive.sub"]` に保存する。
- **Google ログイン成功直後**に、保存 `sub` と現在の `sub` を比較する。
- **保存 `sub` があり、かつ不一致** → アカウント変更とみなしてプロンプトを出す。
- 初回（保存 `sub` なし）や同一アカウント（同 `sub`）では何も起きない。

## 2. プロンプト（2 択）

```
Google アカウントが変わりました
[初期化する]  [ログアウトする]
```

- **表示中は Drive 同期を実行しない**（新アカウントのトークンで前アカウントのデータを
  新アカウントの Drive へ上げない。判定が決まるまで同期はブロック）。
- プロンプトは**モーダル**（選択するまで本棚操作は続行可能だが Drive 同期は止まる）。

## 3. 初期化する → 確認ダイアログ

```
本と進捗を消して、新しいアカウントで作り直します。
（本棚・読書進捗・タグ・閲覧履歴・保存した本のデータ・表紙キャッシュを削除します。取り消せません）
[キャンセル]  [初期化する]
```

- **削除**:
  - ローカル DB: `books` / `bookshelf_items` / `reading_progress` / `book_tags` / `view_history` / `page_views` ほか
  - **保存した本のデータ**（`.opfspack`）
  - 表紙キャッシュ（`thumbnails/`）
  - Drive 系設定: `drive.sub` / `drive.sync.folder_id` / `drive.sync.enabled`
- **残す**: TBF / BOOTH のログインセッション（再同期・再ダウンロードが 1 クリックでできるように）。

## 4. 初期化 実行後 → 「再取得を促す」メッセージダイアログ

```
初期化が完了しました。
技術書典 / BOOTH の本を再度取得してください。
[同期する]  [OK]
```

- 本棚が空になったので、**ユーザに再取得を促す**（自動では同期しない）。
- **[同期する]** を押すと TBF / BOOTH 同期（`bookshelf_items` 再取得・本の再ダウンロード）。
  **[OK]** は何もしない（あとで手動同期）。
- 新アカウントの Drive フォルダは次回同期時に作成される。

## 5. ログアウトする

- **Google ログアウトのみ**（データは無傷）。
- 未暗号化（直接ダウンロード）の本は読める。前アカウントの `sub` で暗号化した本は
  ログイン誘導（読めない）。
- TBF / BOOTH の本・進捗・タグはそのまま。

## 6. キャンセルの挙動

- **確認ダイアログをキャンセル → ログアウト状態に戻す**。
  - 理由: 「別アカウントでログイン中 + 前アカウントのデータ残存」が一番悪い中途半端状態。
    キャンセル時はログアウトして、その中途半端を残さない。
- プロンプト自体を閉じた場合も同様に **ログアウト扱い** に統一する。

## 用語（UI）

- 「パック」は内部識別子（`.opfspack`）のみ。**UI では「保存した本のデータ」** と表示する。

## 解決する不整合（アカウント切替クラスタ）

| 問題 | この設計での扱い |
|---|---|
| 前 `sub` で暗号化した Pack が読めない | 「初期化（消す）or ログアウト（読めないまま戻す）」の 2 択で、中途半端を作らない |
| Drive フォルダが前アカウントのまま | 初期化で `folder_id` リセット → 新アカウント用に再作成。ログアウトなら同期オフ |
| 前アカウントのバックアップが見えない | アカウントごと、が仕様。旧バックアップが必要なら旧アカウントで、と明確 |

## 実装時に留意する点

- **OAuth クライアント変更で `sub` が変わり得る**（同一ユーザでも検知するまれケース）→
  ユーザは「ログアウト」で安全に戻せる。初期化を選んだ場合はユーザの選択。
- **初期化の一部失敗**（DB 削除エラー等）→ ベストエフォート + エラー表示。可能な範囲で部分的に進め、
  失敗箇所を明示する。
- **[同期する] / [OK]** の配置: `[同期する]` を primary、`[OK]` を secondary にする。

## 対象外（別途対応）

アカウント切替とは無関係で、この設計では扱わない不整合:
- 複数デバイス同期の進捗・タグ競合（B1 / B3 / B4）
- Pack の実在（欠落・孤児・置き換え: C1〜C3）
- お気に入り / 非表示の二重管理（D1）

# ~~補足: 未ログイン時（サブキー無し pack）の対応~~（不採用）

> ⚠️ この節（Plan B: `books.identity_sub` を平文で持つ、ログイン中は未DL扱い→再DLでサブキー付きへ差し替え）は**不採用**です。
> 最新は末尾の**改訂版**。未所属 pack は**再暗号化・再DLせずそのまま保持**する方針に変更。
> （採用版では `books.owner_sub` を**暗号化**して保存し、未所属 is `NULL` で保持する）

アカウント切替と密接に関わるため、未ログイン時のダウンロード〜ログインの挙動を定める。
**「ログイン中の本はすべて、自分の `sub` で暗号化された pack」** に揃える方針。
未ログイン時の未暗号化 pack はログイン後に再取得して差し替える（サブキー付きへ）。

> 背景: ローカル DL は常に `identity=None` で import され**未暗号化**になる（Web 版と違い、
> デスクトップ版は DL 時に sub を使わない）。一方、サブキー付き pack は `sub` に紐づくため、
> 未ログイン時の DL とログイン後の DL で「サブキーの有無」が混在する。その不整合を
> 「`books.identity_sub` で管理し、ログイン中は未暗号化を未 DL 扱い → 再取得でサブキー付きへ」で畳む。

## データモデル（Plan B）

`books.identity_sub TEXT`（NULL 許容）を追加する。

| `books.identity_sub` | 意味 |
|---|---|
| `NULL` | **未暗号化**（サブキー無し。未ログイン時 DL の pack） |
| `{sub}` | その `sub` で暗号化した pack（正しいサブキーで復号できる） |

- 暗号化の有無・所有者は**この列だけで判定**する。pack ヘッダの `IDENTITY_BOUND` /
  復号プローブは使わない（カード生成・アップロード判定を軽くするため）。
- **セット箇所は 2 つだけ**:
  - インポート時（`finish_import` — identity を知っている）
  - Drive 同期のダウンロード時（`import_book` — `identity_sub` を受けている）
- 既存のローカル DL はすべて未暗号化（`identity=None`）なので、既存 `books` 行は
  `NULL` で初期化する。Drive 同期で取得済みのサブキー付き pack は、次回の
  インポート/同期で `identity_sub` が補完される（必要なら初回のみヘッダ判定でバックフィル）。

## ① 未ログイン時の DL → サブキー無し

- 現状どおり `download_item` は `identity=None` で import → **未暗号化 pack**。
- `books.identity_sub = NULL` になる。どの Google アカウントとも紐づかない。
- この本は（未ログイン中なら）カードは DL 済み表示・そのままビューアーで読める。

## ② ログイン中は「サブキー無し」を未 DL 扱いにする

- ログイン中は `books.identity_sub IS NULL` の本をカードで**「未 DL」表示**にする。
- クリックすると**再フェッチ** → **サブキー付きで差し替え**。
  - 再フェッチ時は既存 book の id を `identity.pack_id` に再利用して**重複させず上書き**
    （進捗・タグ・閲覧履歴は同じ book id なので維持される）。
- 差し替え後は `identity_sub = 現在 sub` になり、「DL 済み・サブキー付き」として扱われる。
- ⚠️ 結果: ログイン中は、再 DL してサブキー付きにしない限り、その本を開けなくなる
  （カードが未 DL 扱いになり、クリック＝再 DL。オフラインでは読めない）。

## ③ Drive アップロード = 対象アカウントのサブキー付き pack のみ

アップロード判定を `books.identity_sub` で行う。

| `books.identity_sub` | Drive へアップロード |
|---|---|
| `NULL`（未ログイン分・未暗号化） | ❌ しない |
| `!= 現在 sub`（別アカウントの pack） | ❌ しない |
| `== 現在 sub` | ✅ する |

- SQL 比較だけで済む（復号プローブ・ヘッダ判定不要）。
- **未暗号化 pack は Drive に上げない** → 未ログインのままの本は Drive バックアップ対象外
  （仕様として許容）。

## ④ 設定の「ローカルデータ削除」→ 未ログイン分も全部削除（ログイン中でも）

- `delete_all_data`（SettingsView）は **sub キー・ログイン状態を一切見ずに全部消す**
  （全テーブル + `packs/` / `thumbnails/` / `downloads/` の `remove_dir_all`）。
- **現状実装済み。これを不変条件として維持**（この削除にサブキーガードを**入れない**）。
  - この「設定からの全削除」は、上の「初期化する」（§3）とは別物。どちらも全削除だが、
    「初期化」はアカウント切替時の 2 択の一方、「設定の全削除」は常設の操作。

## 状態ごとの挙動

| 状態 | `identity_sub = NULL`（サブキー無し） | `== 現在 sub` | 別 `sub`（前アカウント） |
|---|---|---|---|
| 未ログイン | DL 済み・ビューアーで読める・Drive へ上げない | （通常存在しない） | — |
| ログイン中 | **未 DL 扱い** → 再 DL でサブキー付きへ差し替え | DL 済み・読める・Drive に上げる | （開けない＝ログイン誘導） |
| ログアウト | そのまま読める | 読めない（ログイン誘導） | 読めない |

## 用語: 2 種類の `sub`（混同しない）

この設計には **2 つの sub 概念**がある。別物。

| フィールド | 場所 | 用途 |
|---|---|---|
| `drive.sub` | `app_settings` | アカウント切替の**検知**用（「最後に Drive セットアップした sub」） |
| `books.identity_sub` | `books` テーブル | 各 pack の**暗号化所有者**（サブキー） |

- `drive.sub` は「別アカウントでログインしたか」の判定基準。
- `books.identity_sub` は「この本の pack がどのサブキーで暗号化されているか」。
- 未ログイン→ログイン（初回）は `drive.sub` 未保存なので**アカウント切替扱いにならない**
  （§1）。一方 `books.identity_sub` は関係なく、ログイン中は「未 DL 扱い」の対象になる。

# 改訂版（採用）: データ保持＆属性付け・ログイン切替モデル

> 上記の旧仕様（1 アカウント = 1 プロファイル / 2 択の初期化・ログアウト、および Plan B 案）は
> **不採用**。本節が現行の採用仕様。

## 基本原則

- ローカルの各本（pack）は**所有者**を持つ：ある Google `sub`、または**未所属（NULL）**。
- **複数アカウントのデータは共存**でき、それぞれ**属性付け**される。
  - ※ これは**内部実装**（DB の属性付け）。**ユーザには表立って出さない**。
    アカウント切替は「ログインし直すだけでそのアカウントのデータが見える」だけ。
    専用のアカウント選択・切替 UI は作らない。
- **未所属 pack はそのまま保持**（再暗号化・再DLしない）。未暗号化のまま。**表示・閲覧は
  ログアウト中のみ**（ログイン中は非表示）。
- Google アカウントの切替 = **表示・復号可能データの切替**。データは**削除しない**。
- **ログイン中は現在ログイン中のアカウントのデータのみ**、**ログアウト中は未所属（未暗号化）の
  データのみ**が読める（keyring にトークンは 1 つだけ）。

## データモデル

`books.owner_sub`（**暗号化済み**の所有者 sub、NULL = 未所属・未暗号化）

- **暗号化は必須**：平文 sub を DB に置くと `pack key = PBKDF2(sub + APP_SALT) → HKDF(salt = pack_id)`
  を導出できてしまう（`pack_id` は平文で `books` にある）。→ keyring のローカル鍵
  （例 `thundoku-shelf.db-key`）で AES 暗号化して保存。
- `NULL` = 未ログイン時 DL（未暗号化 pack）→ **そのまま保有**
- `値` = その sub で暗号化された pack（所有者）

> 注: `owner_sub`（pack の暗号化所有者）と、旧仕様の `drive.sub`（アカウント切替の検知用、
> `app_settings`）は**別物**。採用版では `drive.sub` による検知自体を使わない（下記）。

## 所有者ごとの挙動

| 所有者 | 生成されるタイミング | 表示 | 読める | Drive アップロード |
|---|---|---|---|---|
| `NULL`（未所属） | **ログイン中でない**時の DL | **ログアウト中のみ表示** | そのときだけ読める（未暗号化） | ❌ しない |
| `= 現在 sub` | そのアカウントでログイン中の DL | 表示 | 読める | ✅ する |
| `≠ 現在 sub` | 他のアカウントで DL | 非表示 | 読めない（キーが無い） | ❌ しない |

## ログイン・切替・ログアウト

- **DL の挙動**：ログイン中（sub S）だと `owner_sub = S` で暗号化。**ログイン中でない**と
  `owner_sub = NULL` で未暗号化。
- **ログイン**：未所属 pack は**そのまま**（何も書き換えず、再暗号化・再DLしない）。
  現在 sub のデータ**のみ表示**（未所属 pack は非表示）。
  - ※ 未所属しか持ってない場合、ログインすると**本棚は空になり得る**が、これも仕様
    （ユーザには表立って出さない）。
  - **重複は `(source, owner)` で抑止**（source = `site_id + tbf_product_id`）：
    - 再DLの owner が**既存行と同じ**（同一 source・同一 owner）→ **既存行を更新**（同じ book id を使い、
      進捗・タグ・履歴維持。pack を現在 owner で再ビルド）。
    - 再DLの owner が**既存行と違う**（別アカウント、または未所属 NULL）→ **別の行**を追加
      （各アカウントのライブラリ + 未所属）。
      - ※ 未所属（NULL）の本をログイン中に再DLしても、**NULL 行は更新されない**（未所属→所属の
        自動変換はしない）。所属行が別途追加され、両方が共存する（両方管理できる）。
  - （実装）`(source, owner)` の重複抑止は**実装済み**。`books::find_by_source`
    （`site_id + tbf_product_id` で既存行を取得）と `books::resolve_reuse_id`（owner を復号比較し、
    同一 owner の行 id のみ返す。別 owner / 未所属 NULL は対象外）で再利用 id を決め、
    `download_item` から各取り込み関数へ `reuse_book_id` として渡す
    （PDF / EPUB / ZIP / 画像の全経路。画像は `import_image_bytes` にも配線済み）。
    再利用時は同じ book id のまま `books::upsert` で置き換えるため、book_id 紐付けの
    進捗・タグ・閲覧履歴は維持される。
- **フィルタ（表示・アップロード判定）**：`owner_sub` を復号して比較するため、ログイン時に
  `book_id → sub` の**メモリキャッシュ**を作る（起動時1回。本棚300件での毎復号を避ける）。
- **切替（別アカウントでログイン）**：前アカウントのデータは**削除しない**・属性付けたまま
  保持・**非表示**。現在アカウントのデータ**のみ表示**（未所属は非表示）。**2 択（初期化/ログアウト）は廃止**。
- **ログアウト**：Google ログアウトのみ。表示は**未所属（未暗号化）の本だけ**。sub 付きの本は
  **非表示**（読もうとしたらログイン誘導）。

## Drive 同期（所有者連動）

- `drive.sync.folder_id.{sub}` で**アカウントごとに別フォルダ**。
  切替時は前アカウントのフォルダに触らない。
- **アップロード**：`owner_sub == 現在 sub` のみ。NULL・他 sub は上げない。
- **ダウンロード**：現在 sub のフォルダから（自分の pack だけ）。インポート時は
  `owner_sub = 現在sub` をセットする。
  - **所有者確認（metadata プローブ）は行わない**。`folder_id.{sub}` でフォルダが
    アカウントごとに分離されている前提で帰属を信頼する（複数アカウント対応は内部実装）。
- **DB バックアップ**（`thundoku-backup.json`）は **owner == 現在 sub のデータだけ**にフィルタして
  現在 sub の Drive にアップロード → **真にアカウントごとに独立**（他アカウント・未所属のメタは混ぜない）。

## セキュリティ / リスク

- `owner_sub` は暗号化して保存。**DB だけでは pack キーを導出できない**。
- `owner_sub` が**唯一の所有者記録**（pack ファイルには sub が無い）。
  - **現在ログイン中のアカウント**の sub は `google_profile`（keyring のトークン）から
    復元できるため、`owner_sub` 破損でも pack は復号できる。
  - **非現在アカウント**の `owner_sub` は復元手段がなく、破損・消失でその pack は読めない
    （データ損失。許容）。
- **keyring（DB-key・Google トークン）を失うと**、`owner_sub` の復号・所有者復元ができなくなり、
  属性・pack が読めない（ログイン状態も失われる）。

## 既存データ

- **開発版のため、既存データは削除して新モデルで開始する**（マイグレーション・
  `owner_sub` のバックフィルは行わない）。既存データは初回起動時にクリアする。

## 不採用になった旧仕様（対応表）

| 旧仕様 | 判定 |
|---|---|
| 1 アカウント = 1 プロファイル / 切替 = 2 択（初期化・ログアウト） | ❌ 不採用（データ保持＆属性付け・ログイン切替へ） |
| ログイン中、未所属 pack は「未 DL 扱い」→ 再DLでサブキー付きへ差し替え | ❌ 不採用（そのまま保持） |
| `books.identity_sub` を平文で持つ | ❌ 不採用（`books.owner_sub` を暗号化して持つ） |
| Drive アップロード = 現在 sub の pack のみ（Plan B の仕様③） | ✅ 踏襲（表現が `owner_sub` に統一） |

# 実装上の確定事項（おすすめ方針）

上記の採用仕様を TDD で実装する際に、仕様から一意に決まらない部分をここで確定する。
（コードで ad-hoc に決めさせないためのメモ。）

## P1. `owner_sub` の暗号化形式と DB-key のライフサイクル

- **暗号化形式**：AES-256-GCM。`IV（12byte）|| ciphertext || tag` を BASE64 にして
  `books.owner_sub`（TEXT）に保存。`NULL` = 未所属（未暗号化）。
- **DB-key**：keyring の `thundoku-shelf.db-key`（ランダム 32 byte。初回使用時に生成）。
  - **起動時に無い場合 → 新規生成**する（dev 版・既存データ削除予定なので、古い `owner_sub` は復号不能になるが許容）。
  - 復号不能な `owner_sub` は「未知の所有者」として**未所属（NULL）扱いにはしない**（表示は非表示に留める）。

## P2. 暗号化された `owner_sub` は SQL でフィルタできない

- `owner == 現在sub` を SQL で絞れない（暗号化のため）。**フィルタはアプリ側で行う**。
  - ログイン時に `books::list()` で全件ロード → 各 `owner_sub` を復号 → `book_id → sub` のメモリキャッシュ構築。
  - その後の**表示・アップロード・バックアップ**のフィルタは、この**メモリキャッシュで判定**する
    （`book_id → sub` が現在 sub or NULL扱い かどうか）。
  - `books::list` 等は owner 列で SQL フィルタせず、**全件 + メモリフィルタ**に変更する。

## P3. バックアップの owner フィルタは複数テーブルに波及

- `backup::export_json` の owner フィルタは、`books` を絞るだけでなく、**絞った book_id 集合に連動して
  関連テーブルも除外**する（`reading_progress` / `book_tags` / `view_history` / `page_views` 等）。
  - 実装：`books` の owner フィルタで出た book_id 集合をキーに、関連テーブルの行も絞って出力。

## P4. 「初回起動時の既存データクリア」のトリガー

- `app_settings` に `owner_sub_model.initialized` フラグを持つ。
  - **初回起動（フラグ無し）**：既存データを全削除 → フラグをセット。
  - **2 回目以降（フラグ有り）**：触らない。

## P5. `(source, owner)` 重複抑止の book id 決定

- **新規**（その source の既存行が無い / owner が一致しない）：新しい book id（UUID）を割り当て、
  `identity.pack_id` に使う。
- **既存更新**（source + owner 一致）：**既存の book id** を `identity.pack_id` にして更新。
- `book_id_for(Some(identity))` が `identity.pack_id` を返す仕組みと噛み合わせる。
- **未所属（NULL）行は更新しない**（自動変換なし）。所属行を別途追加する。
- **実装**: `download_item` が `books::resolve_reuse_id`（`site_id + tbf_product_id` の lookup +
  owner 復号比較）で `reuse_book_id` を求め、各取り込み関数（`import_image_bytes` を含む）へ渡す。
  `import::book_id_for` は `reuse_book_id` を最優先、無ければ `identity.pack_id`、最後に新規 UUID。
